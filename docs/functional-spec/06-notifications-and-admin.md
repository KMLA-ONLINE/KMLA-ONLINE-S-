# 알림 및 관리

## 14. 알림

### 14.1 알림함

- 알림을 최근 24시간과 이전 알림으로 구분한다.
- 읽지 않은 알림을 배경과 표시점으로 구분한다.
- 한 알림은 표시 신원, 출처 그룹과 활동 시각을 한 줄에 함께 표시하고 알림 내용을 그 아래 최대 세
  줄로 표시한다. 그룹과 무관한 알림에는 그룹 이름을 표시하지 않는다.
- 알림을 개별적으로 읽음 처리하거나 읽지 않은 알림을 모두 읽음 처리할 수 있다.
- 알림을 선택하면 관련 그룹, 프로필 타임라인 또는 게시물로 이동하고 읽음 처리한다.
- 이전 알림을 추가로 불러올 수 있다.
- 읽지 않은 알림 배지는 최근 24시간의 알림을 기준으로 한다.
- 알림은 최대 30일 동안 보관하며 연결된 대상이 영구 삭제되면 함께 삭제될 수 있다.

메시지의 읽지 않음 상태와 알림은 일반 알림함에 넣지 않고 대화별로 관리한다.

### 14.2 중요도 및 전달 채널

알림은 다음 중요도와 기본 전달 정책을 사용한다.

| 중요도    | 기본 전달 정책                                                                                                    |
| --------- | ----------------------------------------------------------------------------------------------------------------- |
| 낮음      | 인앱에만 표시한다. 별도로 명시한 유형은 사용자가 직접 켠 경우에만 Web Push를 보낸다.                              |
| 보통      | 인앱에 표시하고 Web Push를 기본으로 켠다. 사용자는 전체, 유형별, 그룹별 또는 대화별 설정에서 끌 수 있다.          |
| 높음      | 인앱에 표시하고 Web Push를 기본으로 켠다. 운영 조치와 보안 알림은 별도로 정한 범위에서 일반 알림 설정을 무시한다. |
| 외부 필수 | 앱 접근 여부와 관계없이 이메일 등 앱 밖의 채널로 반드시 전달하고 인앱과 Web Push는 보조 채널로 사용한다.          |

Web Push에는 다음 공통 규칙을 적용한다.

- Web Push 전체 설정과 운영체제 또는 브라우저의 알림 권한이 모든 앱 내부 설정보다 우선한다.
- Web Push 전체 설정은 기기별로 적용하고, 유형별·그룹별 설정은 같은 계정의 모든 기기에 적용한다.
- 보통 중요도 유형은 Web Push 전체 설정을 켤 때 기본으로 켜며 사용자가 원하면 유형별로 끈다.
- 낮은 중요도 유형의 Web Push는 기본으로 끄고, 지원하는 유형만 사용자가 직접 켤 수 있다.
- 그룹 콘텐츠의 앱 알림함 수준과 Web Push 설정은 분리한다. Web Push를 꺼도 앱 알림함 수준은 유지한다.
- Web Push는 해당 활동을 앱 알림함에서도 받는 경우에만 켤 수 있으며 Push만 단독으로 받는 조합은 제공하지 않는다.
- 운영 조치는 Web Push 전체 설정이 켜져 있는 동안 유형별, 콘텐츠별 및 그룹별 수신 거부와 관계없이 보낸다.
- Web Push를 받을 수 없거나 발송에 실패해도 인앱 알림은 유지한다.

### 14.3 콘텐츠 알림

| 활동                                               | 수신자                         | 중요도 |
| -------------------------------------------------- | ------------------------------ | ------ |
| 내 게시물에 댓글이 등록됨                          | 게시물 작성자                  | 보통   |
| 내 댓글에 답글이 등록됨                            | 부모 댓글 작성자               | 보통   |
| 게시물에서 내가 멘션됨                             | 멘션된 사용자                  | 보통   |
| 댓글에서 내가 멘션됨                               | 멘션된 사용자                  | 보통   |
| 내 게시물 또는 댓글에 새 반응이 등록됨             | 게시물 또는 댓글 작성자        | 낮음   |
| 다른 사용자가 내 타임라인에 개인 게시물을 작성함   | 타임라인 당사자                | 보통   |
| 타임라인 당사자가 내가 작성한 개인 게시물을 삭제함 | 게시물 작성자                  | 보통   |
| 내가 속한 그룹에 새 게시물이 등록됨                | 그룹 알림 수준이 `전체`인 멤버 | 낮음   |

비공개 개인 게시물에서는 콘텐츠 알림을 만들지 않는다.

게시물 또는 댓글 반응은 인앱에만 표시하고 Web Push를 지원하지 않는다. 새 그룹 게시물은 인앱에 표시하며 사용자가 해당 그룹에서 새 게시물 Push를 직접 켠 경우에만 Web Push를 보낸다.

### 14.4 그룹 운영 알림

| 활동                                           | 수신자                  | 중요도 |
| ---------------------------------------------- | ----------------------- | ------ |
| 새 가입 요청이 접수됨                          | 그룹 소유자와 관리자    | 보통   |
| 내 가입 요청이 승인됨                          | 신청자                  | 보통   |
| 내 가입 요청이 거절됨                          | 신청자                  | 보통   |
| 내 그룹 역할이 변경됨                          | 역할이 변경된 멤버      | 보통   |
| 그룹 소유권이 이전됨                           | 새 소유자와 기존 소유자 | 높음   |
| 공식 그룹에 자동 가입됨                        | 자동 가입된 사용자      | 보통   |
| 가입, 활동 신원 또는 게시물 작성 정책이 변경됨 | 현재 멤버               | 보통   |
| 비공식 그룹이 영구 삭제됨                      | 삭제 시점의 현재 멤버   | 높음   |

현재 그룹 초대는 수신자를 지정하지 않는 공유 링크 방식이므로 초대 알림을 만들지 않는다. 추후 사용자 지정 초대를 추가하면 다음 정책을 적용한다.

- 특정 사용자가 그룹에 초대되면 초대 대상에게 보통 중요도의 인앱 알림과 기본 활성 Web Push를 보낸다.
- 이미 멤버인 사용자는 초대할 수 없고, 같은 사용자와 그룹 조합에는 활성 초대를 하나만 둔다.
- 초대가 취소되거나 만료되면 기존 인앱 알림의 상태를 갱신하고 새 알림이나 Web Push를 만들지 않는다.
- 초대를 수락하면 그룹 관리 상태를 갱신하되 초대한 운영자에게 별도 Push를 보내지 않는다.
- 대기 중인 가입 요청이 있는 사용자가 초대를 수락하면 가입 요청과 초대를 하나의 가입 결과로 정리한다.

### 14.5 운영 조치 알림

다음 알림은 높음 중요도를 사용한다.

- 익명 활동이 제한됨
- 내 게시물이 운영자에 의해 삭제됨
- 내 댓글이 운영자에 의해 삭제됨

삭제된 콘텐츠는 다시 열어볼 수 없으므로 운영 조치 알림이 대상을 밝힌다. 게시물 삭제 알림은 삭제된
게시물의 제목을, 댓글 삭제 알림은 그 댓글이 달려 있던 게시물의 제목을 함께 표시한다. 삭제된 댓글
원문은 알림과 Push 어디에도 표시하지 않는다.

운영 조치 알림은 항상 인앱에 생성한다. Web Push 전체 설정과 브라우저 권한은 존중하되, Web Push가 가능한 상태에서는 일반 콘텐츠, 유형별 및 그룹별 알림 설정과 관계없이 전달한다. 이미 적용 중인 익명 제한을 다시 적용하거나 제한이 만료 또는 수동 해제될 때에는 새 알림을 만들지 않는다.

### 14.6 계정 및 권한 알림

| 활동                              | 수신자      | 중요도 및 전달                                                        |
| --------------------------------- | ----------- | --------------------------------------------------------------------- |
| 학교 프로필 승인 신청이 접수됨    | 앱 관리자   | 낮음, 관리자 대기 인원 배지로 표시하고 개별 Push는 보내지 않음        |
| 가입이 승인됨                     | 신청자      | 높음 및 외부 필수, 이메일을 보내고 가능한 경우 인앱과 Web Push도 사용 |
| 가입이 차단됨                     | 신청자      | 높음 및 외부 필수, 이메일을 보내고 가능한 경우 인앱과 Web Push도 사용 |
| 차단이 해제됨                     | 신청자      | 높음 및 외부 필수, 이메일을 보내고 인앱과 가능한 경우 Web Push도 사용 |
| 앱 관리자로 임명됨                | 대상 사용자 | 높음                                                                  |
| 앱 관리자에서 강등됨              | 대상 사용자 | 높음                                                                  |
| 공강 관리 권한이 부여 또는 회수됨 | 대상 사용자 | 보통                                                                  |
| 비밀번호가 변경 또는 초기화됨     | 계정 소유자 | 외부 필수, 이메일을 보냄                                              |
| 계정 탈퇴가 완료됨                | 탈퇴 사용자 | 외부 필수, 기존 가입 이메일로 완료 알림을 보냄                        |

가입 승인, 차단 및 차단 해제 이메일에는 처리한 관리자의 신원이나 차단 사유를 넣지 않는다. 차단 해제 이메일에는 학교 프로필을 수정해 다시 제출할 수 있음을 안내한다.

### 14.7 학교 부가 기능 알림

| 활동                                      | 수신자                          | 중요도 및 전달                                  |
| ----------------------------------------- | ------------------------------- | ----------------------------------------------- |
| 관리자 선예약으로 장기 공강 예약이 종료됨 | 기존 예약자                     | 높음                                            |
| 공강 또는 노래방 예약 시간이 다가옴       | 예약자 또는 예약 참여자         | 보통, 사용자가 리마인더를 직접 켠 경우에만 전달 |
| 주간 예약 접수가 시작됨                   | 알림을 직접 켠 이용 가능 사용자 | 낮음                                            |
| 동아리 모집이 시작되거나 마감이 임박함    | 알림을 직접 켠 승인 사용자      | 낮음                                            |

예약 등록과 삭제, 동아리 지원과 취소처럼 사용자가 직접 수행해 즉시 결과를 확인하는 작업에는 별도 인앱 알림을 만들지 않는다. 동아리 지원 결과 상태를 추후 추가하면 신청자에게 높음 중요도의 인앱 알림과 기본 활성 Web Push를 보낸다.

### 14.8 알림 신원 표시

- 실명 활동은 이름과 프로필 사진을 표시한다.
- 익명 활동은 실제 신원을 표시하지 않는다.
- 운영진 명의 활동은 `운영진`으로 표시한다.
- 탈퇴한 사용자의 실명 활동은 `탈퇴한 사용자`로 표시한다.
- 익명 제한과 콘텐츠 삭제를 수행한 운영자의 신원은 표시하지 않는다.
- 삭제된 댓글 원문은 알림에 표시하지 않는다.

Web Push에는 화면을 여는 데 필요한 최소 정보만 넣는다. 메시지 본문, 삭제된 콘텐츠 원문, 내부 사용자 식별자 및 공개할 필요가 없는 개인정보는 잠금 화면에 노출하지 않는다.

### 14.9 중복 알림 방지

- 자신의 활동에 대해서는 자신에게 알림을 보내지 않는다.
- 한 댓글이 게시물 댓글과 답글 조건을 동시에 충족하면 더 구체적인 답글 알림 하나만 보낸다.
- 기존 댓글 알림에 멘션이 추가되면 별도 알림을 중복 생성하지 않고 기존 알림을 멘션 알림으로 반영한다.
- 같은 사용자가 반응을 변경하거나 제거해도 새 알림을 만들지 않는다.
- 여러 사용자의 반응은 대상 게시물 또는 댓글 단위로 기존 인앱 알림에 집계한다.
- 집계 알림에 새로운 사용자의 반응이 추가되면 읽지 않음으로 되돌리고 최근 활동 시각을 갱신한다. 최근 24시간 구분과 30일 보존도 이 시각을 기준으로 한다.
- 소유권 이전은 각 대상에게 역할 변경과 소유권 이전 알림을 따로 만들지 않고 하나의 결과로 전달한다.

### 14.10 Web Push 권한 안내

- 가입 승인 후 처음 앱에 진입하면 Web Push의 용도를 설명하는 자체 안내를 먼저 표시한다.
- 사용자가 안내에서 알림 받기를 명시적으로 선택한 경우에만 브라우저 권한을 요청한다.
- 안내를 닫거나 권한 요청을 거절해도 앱 이용을 막지 않는다.
- 권한을 거절한 뒤에는 브라우저 권한 요청을 반복하지 않고 알림 설정에서 브라우저 설정 변경 방법을 안내한다.
- 사용자는 나중에 알림 설정에서 Web Push를 켤 수 있다.
- 권한을 허용하면 보통 및 높음 중요도 Web Push를 기본으로 켜고 낮음 중요도 Web Push는 기본으로 끈다.

## 15. 메뉴 및 개인 설정

### 15.1 메뉴 홈

메뉴에는 다음 항목을 제공한다.

- 내 계정 카드
- 내 프로필
- 비밀번호 변경
- 알림 설정
- 실험실 기능 설정
- 오늘의 급식
- 오픈소스 라이선스
- 로그아웃

앱 관리자에게는 다음 관리 항목을 추가로 제공한다.

- 관리자 허브로 이동하는 단일 바로가기

관리자 허브에서 가입 승인과 차단, 권한 기반 기능 관리자, 앱 관리자 명단을 한 곳에서 관리한다.

### 15.2 알림 설정

- Web Push 전체 설정과 현재 브라우저 권한 상태를 표시한다.
- Web Push를 지원하지 않는 환경에서는 지원하지 않음을 안내하고 켜기 기능을 제공하지 않는다.
- 브라우저 권한이 거절된 상태에서는 권한 요청을 반복하지 않고 브라우저 설정 변경 방법을 안내한다.
- Web Push 전체 설정을 켜면 보통 및 높음 중요도 유형을 기본으로 켠다.
- Web Push 전체 설정을 변경하는 동안 진행 상태를 표시하고 중복 조작을 막는다.
- 사용자는 댓글·답글·멘션, 타임라인 활동, 그룹 가입·역할, 계정·권한 및 학교 기능의 Web Push를 유형별로 끌 수 있다.
- 그룹별로 앱 알림함 수준과 직접 관련 활동 Push를 따로 설정한다. 앱 알림함 수준을 `없음`으로 두면 해당 그룹의 콘텐츠 Push도 함께 끈다.
- 낮음 중요도의 새 그룹 게시물 Push는 앱 알림함 수준이 `전체`인 그룹에서만 직접 켜거나 끈다.
- 게시물, 댓글 및 메시지 반응은 인앱 전용이므로 Web Push 설정을 제공하지 않는다.
- 현재 설정이 실제로 무엇을 전달하는지 요약해 보여주고, 설정을 바꾸면 즉시 갱신한다.
- Web Push 전체 설정은 이 기기에만, 유형별과 그룹별 설정은 계정의 모든 기기에 적용된다는 점을 각 설정 옆에 표시한다.
- 유형별 Web Push를 끄면 해당 알림이 앱 알림함에는 계속 쌓인다는 점을 그 유형에 한해 안내한다.
- 운영 조치는 Web Push 전체 설정이 켜져 있는 동안 항상 전달된다는 점을 안내하고 유형별 끄기 기능을 제공하지 않는다.
- 메시지 알림은 이 화면의 Web Push 전체 설정을 따르되 세부 수신 수준과 일시 중지는 각 대화에서 설정한다.

### 15.3 실험실 기능

- 사용자는 개인 설정에서 실험실 기능을 켜거나 끈다.
- 선택은 기기에 저장한다.
- 실험실 기능이 켜진 경우에만 실험실 설정으로 이동할 수 있다.
- 실험실 기능은 변경되거나 제거될 수 있다.

### 15.4 실험실: 게시물 보기

- 사용자는 카드 보기 또는 목록 보기를 선택한다.
- 선택은 기기에 저장하고 홈 피드와 그룹 게시물 목록에 함께 적용한다.
- 보기 방식은 실험실 설정에서 변경한다.

### 15.5 실험실: 테마

사용자는 다음 화면 테마를 선택한다.

- 시스템 설정 따르기
- 라이트
- 다크

### 15.6 오늘의 급식

- 오늘 날짜를 표시한다.
- 조식, 중식 및 석식 메뉴를 구분해 표시한다.
- 각 식사의 메뉴 항목을 순서대로 표시한다.

### 15.7 오픈소스 라이선스

- 서비스에서 사용하는 오픈소스 및 이미지 자산의 저작권 정보를 표시한다.
- 프로젝트 및 라이선스 원문으로 이동할 수 있다.

## 16. 앱 관리자

### 16.1 가입 신청 목록

- 승인 대기 신청을 오래 기다린 순서로 표시한다.
- 전체 대기 인원을 표시한다.
- 신청자를 개별 또는 복수 선택할 수 있다.

신청자별로 다음 정보를 확인한다.

- 이름
- 사용자 유형
- 재입학 여부
- 신청 시각
- 기수
- 반
- 계열
- 부서
- 학번
- 성별
- 생일
- 전화번호
- 기숙사 방
- 자기소개

### 16.2 가입 승인, 차단 및 해제

- 신청자를 개별 승인 또는 차단한다.
- 선택한 여러 신청자를 한 번에 승인 또는 차단한다.
- 한 번에 최대 200명의 신청을 처리한다.
- 승인된 사용자는 일반 서비스 기능을 이용할 수 있다.
- 차단 사용자 명단을 제공하며, 차단된 사용자는 프로필을 수정하거나 다시 신청할 수 없다.
- 차단을 해제하면 사용자를 프로필 미작성 상태로 전환한다. 사용자는 학교 프로필 설정에서 정보를 수정한 뒤 다시 제출한다.
- 차단 사유는 입력하거나 표시하지 않는다.
- 승인, 차단 및 차단 해제 결과는 가입 이메일로 반드시 보내며 처리한 관리자의 신원과 차단 사유는 넣지 않는다.
- 가능한 경우 같은 결과를 인앱 알림과 Web Push로도 전달하되 이메일을 대체하지 않는다.

### 16.3 앱 관리자 명단 보호

- 앱 관리자 명단과 권한 변경 화면을 열기 전에 현재 비밀번호로 본인을 다시 확인한다.
- 비밀번호 확인 후 5분 동안 관리자 명단 조회, 검색, 임명 및 강등을 허용한다.
- 관리자 명단에 이름, 프로필, 기수 또는 사용자 유형 및 부서를 표시한다.
- 현재 로그인한 관리자에게 `나` 표시를 제공한다.

### 16.4 관리자 후보 검색

- 승인된 일반 사용자를 이름 또는 기수로 검색한다.
- 검색어를 두 글자 이상 입력한 뒤 결과를 표시한다.
- 이름, 기수, 사용자 유형 및 부서를 함께 표시해 동명이인을 구분한다.

### 16.5 관리자 임명 및 강등

- 기존 앱 관리자는 승인된 사용자를 앱 관리자로 임명할 수 있다.
- 앱 관리자는 자신을 포함한 앱 관리자를 일반 사용자로 강등할 수 있다.
- 대상과 권한 변화를 두 단계로 확인한 뒤 적용한다.
- 마지막 한 명의 앱 관리자는 강등할 수 없다.
- 앱 관리자 강등은 해당 사용자의 계정과 개별 그룹 역할에 영향을 주지 않는다.
- 임명 또는 강등 결과는 대상 사용자에게 높음 중요도로 알린다.

### 16.6 권한 기반 기능 관리자

- 승인된 사용자를 이름, 공개 프로필 ID 또는 기수로 검색한다.
- 승인된 사용자에게 공강 관리 권한을 부여하거나 회수한다.
- 공강 관리 권한 조회와 변경에는 앱 관리자 권한이 필요하지만 비밀번호 재확인은 요구하지 않는다.
- 권한 부여 또는 회수 결과는 대상 사용자에게 보통 중요도로 알린다.
