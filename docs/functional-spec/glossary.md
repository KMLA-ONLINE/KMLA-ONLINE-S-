# 용어집

명세와 코드에서 같은 뜻으로 쓰는 도메인 용어를 모았다. 각 용어의 정본 규칙은 링크한 절에 있다.

## 사용자와 학적

| 용어               | 뜻                                                                                         | 코드·스키마 대응                                         |
| ------------------ | ------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| 재학생·졸업생·교사 | 사용자 유형. 학적 정보의 필수 항목과 그룹 이용 범위가 유형마다 다르다 (§2.1)               | `profiles.type` = `student` / `alumni` / `teacher`       |
| 기수               | 입학 연차. 1 이상 100 이하                                                                 | `profiles.cohort`                                        |
| 복학생             | 원래 기수와 함께 생활하는 기수(`cohort + 1`)를 모두 갖는 재학생. 프로필에는 `n.5기`로 표시 | `profiles.is_returning_student`                          |
| 관련 기수          | 피드와 공결 노출 판정에 쓰는 기수 집합. 일반 재학생은 `cohort`, 복학생은 `cohort + 1`까지  | `private.feed_profile_cohorts()`                         |
| 계열               | 국내반 또는 국제반                                                                         | `profiles.academic_track` = `domestic` / `international` |
| 공개 ID            | 프로필 URL에 쓰는 5–15자 문자열. 예약어를 쓸 수 없다 (§12.1)                               | `profiles.pub_id`                                        |
| 앱 관리자          | 가입 심사와 관리자 임명 권한. 개별 그룹의 운영 권한과 별개다 (§2.1)                        | `profiles.role = 'admin'`                                |

## 그룹

| 용어                      | 뜻                                                                        | 코드·스키마 대응                                              |
| ------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 공식 그룹                 | 앱 관리자만 만들고, 승인된 재학생이 자동 가입되는 그룹 (§7.1)             | `groups.kind = 'official'`                                    |
| 비공식 그룹               | 승인 사용자가 자율적으로 만드는 그룹 (§7.1)                               | `groups.kind = 'unofficial'`                                  |
| 가입 정책                 | 공개·즉시 / 공개·승인 / 비공개·초대 전용 (§7.5)                           | `group_join_policy` = `open` / `request` / `invite_only`      |
| 활동 신원 정책            | 실명만 쓸지, 작성할 때 실명·익명을 고를 수 있게 할지 (§8.5)               | `group_identity_policy` = `identified` / `optional_anonymous` |
| 글쓰기 정책               | 모든 멤버가 쓸지, 운영진만 쓸지 (§8.2)                                    | `group_posting_policy` = `members` / `staff`                  |
| 소유자·관리자·매니저·멤버 | 그룹 역할. 매니저는 게시판 운영만 맡고 멤버·정책은 건드리지 않는다 (§2.3) | `group_member_role`                                           |
| 그룹 주소                 | 그룹 상세 URL에 쓰는 4–15자 문자열. 내부 관계는 별도 UUID를 쓴다 (§7.7)   | `groups.slug`                                                 |

## 게시물과 활동

| 용어               | 뜻                                                                                                | 코드·스키마 대응                                       |
| ------------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 그룹 게시물        | 그룹에 속한 게시물. 제목·카테고리·고정을 갖는다 (§8.1)                                            | `posts.kind = 'group'`                                 |
| 개인 게시물        | 프로필 타임라인에 속한 게시물. 제목·카테고리·고정이 없다 (§8.1)                                   | `posts.kind = 'profile'`                               |
| 타임라인           | 한 프로필을 대상으로 작성된 개인 게시물의 목록 (§12.4)                                            | `posts.timeline_profile_id`                            |
| 타임라인 당사자    | 그 타임라인의 주인. 작성자와 다를 수 있다                                                         | 위와 같음                                              |
| 생탐               | 작성자와 타임라인 당사자가 다른 전체 공개 개인 게시물. 피드 노출에 기수·성별 조건이 붙는다 (§6.1) | 피드에서 `is_cross_timeline`                           |
| 프로필 미디어 활동 | 프로필 사진·커버를 바꿀 때 자동으로 생기는 전체 공개 개인 게시물 (§8.4)                           | `posts.activity_kind`                                  |
| `#업`              | 본문이 정확히 `#업`인 최상위 실명·운영진 댓글. 그룹 게시물을 홈 피드 위로 올린다 (§6.2)           | `private.feed_bump_events`                             |
| 작성 신원          | 게시 시점에 정해지고 이후 바뀌지 않는 실명·익명·운영진 구분 (§8.5, §8.6)                          | `post_identity` = `identified` / `anonymous` / `staff` |
| 운영진 명의        | 운영진이 개인 이름 대신 `운영진`으로 쓰는 것. 익명과 달리 실제 작성자를 감추지 않는다 (§8.6)      | `author_identity = 'staff'`                            |
| 글쓴이 · 익명N     | 익명 게시물 안에서 작성자를 `글쓴이`, 다른 익명 참여자를 `익명1`·`익명2`로 구분 (§9.3)            | `post_comments`의 alias 번호                           |

## 학교 기능

| 용어          | 뜻                                                                                   | 코드·스키마 대응                        |
| ------------- | ------------------------------------------------------------------------------------ | --------------------------------------- |
| 공강 예약     | 지하 1층·2층·4층·10층의 시간대를 잡는 예약. 장기 예약과 관리자 선예약이 있다 (§17.1) | `utility_reservations.mode = 'gongang'` |
| 노래방 예약   | 날짜와 시간대를 잡는 일회성 예약 (§17.2)                                             | `utility_reservations.mode = 'karaoke'` |
| 장기 예약     | 같은 요일·장소·시간대를 매주 자동으로 점유하는 공강 예약 (§17.1)                     | `utility_reservations.recurring`        |
| 관리자 선예약 | 공강 관리자가 일반 공개 전에 다음 주 자리를 먼저 잡는 것 (§17.1)                     | `gongang_schedule`                      |
| 공결 · 병결   | 재학생이 오늘 사유를 남기면 같은 노출 기수에게만 보이는 기록 (§6.6, §17.6)           | `student_absences`                      |

## 알림

| 용어               | 뜻                                                                       | 코드·스키마 대응                                             |
| ------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------ |
| 중요도             | 낮음·보통·높음과, 이메일을 반드시 보내는 외부 필수 (§14.2)               | `notification_importance`                                    |
| 앱 알림함 수준     | 그룹별 인앱 알림 범위. 전체 · 직접 관련 · 없음 (§7.16)                   | `group_notification_level`                                   |
| 운영 조치 알림     | 운영자의 콘텐츠 삭제 등, 일반 알림 설정을 무시하고 전달하는 알림 (§14.5) | `notification_category = 'moderation'`                       |
| Web Push 전체 설정 | 기기 단위 설정. 유형별·그룹별 설정은 계정의 모든 기기에 적용된다 (§14.2) | `private.web_push_subscriptions`, `notification_preferences` |
