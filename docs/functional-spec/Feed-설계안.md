# KMLA Online 피드 v1 설계안

> **대체된 제안 문서:** 이 문서는 검토 당시의 제안과 사용자 편집 이력을 보존한다. 현재 요구사항은 [피드 및 그룹](02-feed-and-groups.md), [게시물 및 상호작용](03-posts-and-interactions.md), [홈 통합 피드 랭킹 설계](../FEED_RANKING.md)를 따른다. 특히 이 문서의 피드 읽음 상태·새 글 표시·로컬 방문 표시와 오늘의 생일 제안은 채택하지 않았으며, 운영진 신원 표시는 게시물 기능 명세가 우선한다.

> 공개 개인 게시물과 가입 그룹 게시물을 하나로 합친 최신순 중심 통합 피드.
> v1은 규칙 기반 랭킹만 사용하며, 추천/ML은 사용하지 않는다. 페이지 크기는 20개다.

## 1. 피드 범위

### 포함

- **공개 개인 게시물**
- **현재 가입한 그룹의 게시물**
- **관련 기수 조건을 만족하는 생탐 게시물**

### 제외

- 비공개 개인 게시물
- 가입하지 않은 그룹의 게시물
- 삭제된 게시물
- 그룹 탈퇴 이후 해당 그룹의 게시물
- 관련 기수가 아닌 생탐 게시물

그룹을 탈퇴했다가 다시 가입하면 탈퇴 기간에 올라온 게시물도 다시 후보가 된다.

그룹 내부의 게시물 고정 여부는 피드 정렬에 영향을 주지 않는다.

v1에서는 팔로우/친구, 관심사, 클릭·조회 기록, 개인별 추천 점수, AI/ML 랭킹을 사용하지 않는다.

---

## 2. 기본 랭킹

기본 정렬은 **최신순**이다.

최근 **6시간 이내** 게시물에 한해 댓글·반응을 약하게 반영한다.

여기서 말하는 작성 시각은 게시물이 발행된 시각(`published_at`)이다. 초안을 만든 시각이 아니다.

### 반영 활동

| 활동          | 보정 |
| ------------- | ---: |
| 반응 1개      | +4분 |
| 랭킹 댓글 1개 | +8분 |
| 최대 보정     | 40분 |

**랭킹 댓글**은 다른 사용자가 작성한 **최상위 댓글**만 해당한다.

다음은 랭킹에서 제외한다.

- 작성자가 자기 게시물에 단 댓글
- 답글
- `#업` 댓글
- 삭제된 댓글

### 시간 감쇠

선형으로 오래된 게시물일수록 댓글·반응 보정의 최대 반영 범위가 줄어든다.

| 작성 후 경과 | 최대 반영 범위 |
| ------------ | -------------: |
| 방금 작성    |           40분 |
| 약 1시간     |        약 33분 |
| 약 3시간     |           20분 |
| 약 5시간     |         약 7분 |
| 6시간 이상   |            0분 |

보정값은 다음과 같이 계산한다. `R`은 반응 수, `C`는 랭킹 댓글 수, `경과`는 작성 후 지난 시간이다.

```text
보정 = min(4 × R + 8 × C, 40분 × (1 − 경과 / 6시간))
```

최근 6시간 이내에는 대략 **작성 시각 + 댓글·반응 보정 + 고정 동점 순서**로 정렬한다.

6시간이 지나면 일반 댓글·반응 보정은 종료되고 다시 사실상 최신순으로 처리한다. 단, `#업`은 예외다.

### 랭킹 기준 시각

댓글 수와 반응 수는 **`feed_epoch` 시점의 값으로 고정한다.** `feed_epoch` 이후에 달린 댓글과 반응은 같은 피드 세션 안에서는 순위에 반영하지 않는다.

페이지를 넘길 때마다 다시 세면 그 사이에 순서가 바뀌어 게시물이 중복되거나 누락되기 때문이다. 새 활동은 새로고침한 다음 피드부터 반영한다.

## 3. `#업` — 통합 피드 끌어올림

오래된 공지 등을 다시 노출하기 위한 피드 전용 신호다.

### 적용 대상

- **그룹 게시물에만 적용한다.** 개인 게시물은 `#업` 대상이 아니다.
- 게시물의 **최상위 댓글**이 `#업`이어야 한다. 답글의 `#업`은 적용하지 않는다.
- **익명 댓글의 `#업`은 적용하지 않는다.** 실명과 운영진 댓글만 유효하다.

### 동작

- `#업` 작성 시점을 기준으로 통합 피드에서 게시물을 다시 위쪽에 노출
- 끌어올린 위치는 **다음 유효 `#업`이 있을 때까지 유지**한다
- 그룹 내부 랭킹에는 영향 없음
- 표시 댓글 수에는 포함하지만 일반 댓글 보정에서는 제외
- 같은 게시물에는 **마지막 유효 `#업` 후 1시간** 동안 추가 끌어올림 효과 없음
- 1시간이 지나면 새로운 `#업`으로 다시 끌어올릴 수 있음
- `#업`으로 재노출될 때 과거 댓글·반응 보정을 다시 추가 적용하지 않음
- 기존 피드 후보 조건은 바꾸지 않음
- `published_at`은 그대로 유지하므로 `#업`만으로 새 글이 되지는 않음

---

## 4. 도배 방지 — 노출 제한

| 출처                      | 연속 노출 | 한 페이지(20개) |
| ------------------------- | --------: | --------------: |
| 같은 사용자의 개인 게시물 |  최대 2개 |        최대 4개 |
| 같은 그룹의 게시물        |  최대 3개 |       최대 10개 |

- 서로 다른 그룹은 서로 다른 출처로 취급한다.
- 제한에 걸린 게시물은 숨기거나 삭제하지 않고 **뒤로 이동**한다.
- 페이지가 바뀌면 페이지 내 개수 제한은 다시 계산한다.
- 후보가 부족하면 제한보다 **게시물을 보여주는 것을 우선**한다.

## 5. 페이지네이션과 피드 세션

- 한 번에 **20개**씩 로드한다.
- 하나의 피드 탐색에는 기준 시각(`feed_epoch`)이 있고, 계속 스크롤하는 동안 유지한다.
- 스크롤 도중 새 게시물을 기존 목록 사이에 삽입하지 않는다.
- 새 게시물은 **새로고침**으로 확인한다.
- 새로고침하면 새로운 기준으로 피드를 다시 만든다.

## 6. 피드 게시물 응답 정보

### 공통

- 게시물
- 작성자 신원 구분 — 실명 / 익명 / 운영진
- 작성자 — 신원이 실명일 때만 내려보낸다
- 표시 이름 — 익명은 `익명`, 운영진은 `운영진`
- 작성 시각
- 댓글 수
- 반응 수
- 이미지 및 첨부 파일
- 개인/그룹 게시물 구분

익명 또는 운영진 게시물에는 실제 작성자 정보를 내려보내지 않는다.

### 개인 게시물

- 공개 범위

### 그룹 게시물

- 그룹
- 그룹 이름

## 7. 읽음 상태와 새 글 표시

읽음 상태는 **표시용**이며 랭킹에는 영향을 주지 않는다.

### 저장 값

사용자마다 시각 하나만 저장한다.

```text
profiles.last_feed_seen_at timestamptz NULL
```

- `NULL`: 피드를 한 번도 본 적 없음
- 게시물 단위 읽음 테이블은 만들지 않음

### 갱신 API

런타임에 애플리케이션 서버가 없으므로 RPC로 갱신한다.

```text
mark_feed_seen(p_seen_at timestamptz)
```

규칙:

- `p_seen_at`에는 첫 페이지 응답의 `feed_epoch`을 그대로 사용
- 클라이언트 시계는 사용하지 않음
- `p_seen_at`이 `now()`보다 미래이면 오류로 거절
- 오래된 요청이 늦게 도착해도 시각이 뒤로 가지 않도록 더 최신 값만 저장

```text
last_feed_seen_at =
  GREATEST(COALESCE(last_feed_seen_at, p_seen_at), p_seen_at)
```

### 호출 시점

피드 진입 시가 아니라 다음 시점에 호출한다.

- 피드 화면 이탈
- 탭 전환 / 다른 화면 이동
- 앱 백그라운드 진입
- 피드에서 스크롤이 5초 이상 멈춘 뒤
- 체류 3초 미만이면 생략 가능

### 새 글 판정

```text
post.published_at > viewer.last_feed_seen_at
```

`rank_time`은 사용하지 않는다. `#업`으로 오래된 글이 올라와도 새 글로 표시하면 안 되기 때문이다.

- `last_feed_seen_at == NULL`이면 새 글 표시 없음

### 첫 페이지 추가 필드

| 필드                | 내용                              |
| ------------------- | --------------------------------- |
| `last_feed_seen_at` | 이번 요청 전 저장값, 없으면`null` |
| `new_post_count`    | 새 글 수, 없으면`0`               |

`new_post_count` 규칙:

- 실제 피드 후보 조건과 동일하게 계산
- 본인이 작성한 글은 제외
- `last_feed_seen_at == NULL`이면 `0`
- 99 초과 시 UI에서 `99+`
- 첫 페이지에만 포함

### UI

- 새 글: 항목 옆에 가벼운 점 표시

### 방문 표시

목록 보기에서 이미 열어 본 게시물을 시각적으로 구분한다. 위의 새 글 표시와는 별개다.

- 기기 로컬에만 저장한다. 게시물 단위 읽음 상태를 서버에 기록하지 않는다.
- 랭킹에 영향을 주지 않는다.
- 기기 간에 동기화하지 않는다.

## 8. 생탐 게시물

생탐은 일반 개인 게시물과 같은 피드에 포함하되, **대상자의 관련 기수**를 기준으로 노출한다.

### 후보

- 그룹 게시물이 아닌 개인 게시물
- 작성자와 타임라인 당사자가 서로 다른 경우

### 관련 기수 판정

- **일반 재학생**: 대상자의 현재 기수
- **복학생** (`is_returning_student = true`): 원래 기수(`cohort`)와 함께 생활하는 기수(`cohort + 1`)
- 보는 사용자와 대상자의 관련 기수가 겹치지 않으면 피드에서 제외
- 작성자의 기수가 아니라 **대상자의 관련 기수**를 기준으로 판단
- 관련 기수가 없는 사용자에게는 생탐을 노출하지 않는다. 교사와, 재학 기수와 겹치지 않는 졸업생이 여기 해당한다

### 랭킹

- 최근 6시간 랭킹 구간에서 일반 랭킹 결과보다 **60분 낮게 배치**
- 60분 조정은 관련 기수 조건을 통과한 생탐 전체에 적용한다. 생일 관련 게시물을 따로 구분하지 않는다
- 댓글·반응 보정은 일반 게시물과 동일
- 6시간 이후에는 일반 최신순 규칙 적용
- 개인 게시물이므로 `#업` 대상이 아니다

예: 29기가 복학해 30기와 함께 생활한다면, 해당 학생 대상 생탐은 29기와 30기 모두에게 노출한다.

### 생일 정보

생탐 피드 노출과 별개로 **"오늘의 생일"** 영역에서 당일 생일자를 확인할 수 있게 한다.

## 9. 핵심 상수

| 항목                         |                값 |
| ---------------------------- | ----------------: |
| 페이지 크기                  |              20개 |
| 일반 반응 적용 기간          |     작성 후 6시간 |
| 반응 1개                     |              +4분 |
| 랭킹 댓글 1개                |              +8분 |
| 최대 댓글·반응 보정          |              40분 |

## 10. v1에서 하지 않는 것

- 팔로우/친구 기반 피드
- 사용자별 관심사 추천 및 개인별 추천 점수
- 클릭·조회 기록 기반 랭킹
- AI/ML/임베딩/협업 필터링
- 트렌딩 피드
- 일반 반응만으로 오래된 인기글을 다시 상단에 올리는 처리
- 개인 게시물과 그룹 게시물의 강제 비율
- 작성자·그룹별 하루 게시물 제한
- 게시물 단위 읽음 상태의 서버 저장
- 읽은 글 숨김 또는 순위 하락
- 읽음 상태의 기기 간 실시간 동기화
- 읽음 데이터를 랭킹에 반영
- 개인 게시물의 `#업`
