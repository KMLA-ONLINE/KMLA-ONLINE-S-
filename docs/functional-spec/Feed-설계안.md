# KMLA Online Feed v1 설계안

> 공개 개인 Post와 가입 그룹 Post를 하나로 합친 최신순 중심 통합 Feed.
> v1은 규칙 기반 Ranking만 사용하며, 추천/ML은 사용하지 않는다. 페이지 크기는 20 Posts다.

## 1. Feed 범위

### 포함

- **공개 개인 Post**
- **현재 가입한 그룹의 Post**
- **관련 기수 조건을 만족하는 생탐 Post**

### 제외

- 비공개 개인 Post
- 가입하지 않은 그룹의 Post
- 삭제된 Post
- 그룹 탈퇴 이후 해당 그룹의 Post
- 관련 기수가 아닌 생탐 Post

v1에서는 Follow/Friend, 관심사, 클릭·조회 기록, 개인별 추천 점수, AI/ML Ranking을 사용하지 않는다.

---

## 2. 기본 Ranking

기본 정렬은 **최신순**이다.

최근 **6시간 이내** Post에 한해 댓글·반응을 약하게 반영한다.

### 반영 활동

| 활동             | 보정 |
| ---------------- | ---: |
| 반응 1개         | +4분 |
| Ranking 댓글 1개 | +8분 |
| 최대 보정        | 40분 |

**Ranking 댓글**은 다른 사용자가 작성한 **최상위 댓글**만 해당한다.

다음은 Ranking에서 제외한다.

- 작성자가 자기 Post에 단 댓글
- 답글
- `#업` 댓글

### 시간 감쇠

선형으로 오래된 Post일수록 댓글·반응 보정의 최대 반영 범위가 줄어든다.

| 작성 후 경과 | 최대 반영 범위 |
| ------------ | -------------: |
| 방금 작성    |           40분 |
| 약 1시간     |        약 33분 |
| 약 3시간     |           20분 |
| 약 5시간     |         약 7분 |
| 6시간 이상   |            0분 |

최근 6시간 이내에는 대략 **작성 시각 + 댓글·반응 보정 + 고정 동점 순서**로 정렬한다.

6시간이 지나면 일반 댓글·반응 보정은 종료되고 다시 사실상 최신순으로 처리한다. 단, `#업`은 예외다.

---

## 3. `#업` — 통합 Feed 끌어올림

오래된 공지 등을 다시 노출하기 위한 Feed 전용 신호다.

- Feed 후보 Post의 **최상위 댓글**이 `#업`이면 적용
- 답글의 `#업`은 적용하지 않음
- `#업` 작성 시점을 기준으로 통합 Feed에서 Post를 다시 위쪽에 노출
- 그룹 내부 Ranking에는 영향 없음
- 표시 댓글 수에는 포함하지만 일반 댓글 보정에서는 제외
- 같은 Post에는 **마지막 유효 `#업` 후 1시간** 동안 추가 끌어올림 효과 없음
- 1시간이 지나면 새로운 `#업`으로 다시 끌어올릴 수 있음
- `#업`으로 재노출될 때 과거 댓글·반응 보정을 다시 추가 적용하지 않음
- 기존 Feed 후보 조건이나 생탐 관련 기수 조건은 바꾸지 않음
- `created_at`은 그대로 유지하므로 `#업`만으로 새 글이 되지는 않음

---

## 4. 도배 방지 — 노출 제한

| 출처                    | 연속 노출 | 한 페이지(20개) |
| ----------------------- | --------: | --------------: |
| 같은 사용자의 개인 Post |  최대 2개 |        최대 4개 |
| 같은 그룹의 Post        |  최대 3개 |       최대 10개 |

- 서로 다른 그룹은 서로 다른 출처로 취급한다.
- 제한에 걸린 Post는 숨기거나 삭제하지 않고 **뒤로 이동**한다.
- 페이지가 바뀌면 페이지 내 개수 제한은 다시 계산한다.
- 후보가 부족하면 제한보다 **Post를 보여주는 것을 우선**한다.

---

## 5. 페이지네이션과 Feed 세션

- 한 번에 **20개**씩 로드한다.
- 하나의 Feed 탐색에는 기준 시각(`feed_epoch`)이 있고, 계속 스크롤하는 동안 유지한다.
- 스크롤 도중 새 Post를 기존 목록 사이에 삽입하지 않는다.
- 새 Post는 **새로고침**으로 확인한다.
- 새로고침하면 새로운 기준으로 Feed를 다시 만든다.

## 7. 읽음 상태와 새 글 표시

읽음 상태는 **표시용**이며 Ranking에는 영향을 주지 않는다.

### 저장 값

사용자마다 시각 하나만 저장한다.

```text
profiles.last_feed_seen_at timestamptz NULL
```

- `NULL`: Feed를 한 번도 본 적 없음
- Post 단위 읽음 테이블은 만들지 않음

### 갱신 API

```http
PATCH /feed/seen
Content-Type: application/json

{ "seen_at": "<feed_epoch>" }
```

규칙:

- `seen_at`에는 첫 페이지 응답의 `feed_epoch`을 그대로 사용
- 클라이언트 시계는 사용하지 않음
- `seen_at > now()`이면 `400`
- 오래된 요청이 늦게 도착해도 시각이 뒤로 가지 않도록 더 최신 값만 저장

```text
last_feed_seen_at =
  GREATEST(COALESCE(last_feed_seen_at, seen_at), seen_at)
```

### 호출 시점

Feed 진입 시가 아니라 다음 시점에 호출한다.

- Feed 화면 이탈
- 탭 전환 / 다른 화면 이동
- 앱 백그라운드 진입
- Feed에서 스크롤이 5초 이상 멈춘 뒤
- 체류 1초 미만이면 생략 가능

### 새 글 판정

```text
post.created_at > viewer.last_feed_seen_at
```

`rank_time`은 사용하지 않는다. `#업`으로 오래된 글이 올라와도 새 글로 표시하면 안 되기 때문이다.

- `last_feed_seen_at == NULL`이면 새 글 표시 없음

### 첫 페이지 추가 필드

| 필드                | 내용                              |
| ------------------- | --------------------------------- |
| `last_feed_seen_at` | 이번 요청 전 저장값, 없으면`null` |
| `new_post_count`    | 새 글 수, 없으면`0`               |

`new_post_count` 규칙:

- 실제 Feed 후보 조건과 동일하게 계산
- 본인이 작성한 글은 제외
- `last_feed_seen_at == NULL`이면 `0`
- 99 초과 시 UI에서 `99+`
- 첫 페이지에만 포함

### UI

- 새 글: 항목 옆에 가벼운 점 표시

## 8. 생탐 Post

생탐은 일반 개인 Post와 같은 Feed에 포함하되, **대상자의 관련 기수**를 기준으로 노출한다.

### 후보

- 그룹 Post가 아닌 개인 Post
- 작성자와 Post 대상 프로필이 서로 다른 경우

### 관련 기수 판정

- **일반 재학생**: 대상자의 현재 기수·학년
- **복학생** (`is_returning_school = true`): 원래 기수 + 현재 함께 생활하는 기수
- viewer와 대상자의 관련 기수가 겹치지 않으면 Feed에서 제외
- 작성자의 기수가 아니라 **대상자의 관련 기수**를 기준으로 판단

### Ranking

- 최근 6시간 Ranking 구간에서 일반 Ranking 결과보다 **60분 낮게 배치**
- 댓글·반응 보정은 일반 Post와 동일
- 6시간 이후에는 일반 최신순 규칙 적용
- `#업` 규칙은 그대로 적용

예: 29기가 복학해 30기와 함께 생활한다면, 해당 학생 대상 생탐은 29기와 30기 모두에게 노출한다.

### 생일 정보

생탐 Feed 노출과 별개로 **“오늘의 생일”** 영역에서 당일 생일자를 확인할 수 있게 한다.

| 생탐 최근 Ranking 조정     |             -60분 |

## 10. v1에서 하지 않는 것

- Follow/Friend 기반 Feed
- 사용자별 관심사 추천 및 개인별 추천 점수
- 클릭·조회 기록 기반 Ranking
- AI/ML/Embedding/Collaborative Filtering
- Trending Feed
- 일반 반응만으로 오래된 인기글을 다시 상단에 올리는 처리
- 개인 Post와 그룹 Post의 강제 비율
- 작성자·그룹별 하루 Post 제한
- Post 단위 읽음 기록
- 읽은 글 숨김 또는 순위 하락
- 읽음 상태의 기기 간 실시간 동기화
- 읽음 데이터를 Ranking에 반영

## 최종 정의

**KMLA Online Feed v1은 추천 Feed가 아니라, 최신순을 중심으로 최근 대화와 출처 다양성을 약하게 반영한 통합 Feed다.**
