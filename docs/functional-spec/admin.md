# 앱 관리자

## 16. 앱 관리자

### 16.1 가입 신청 목록

- 승인 대기 신청을 오래 기다린 순서로 표시하고 전체 대기 인원을 함께 보여준다.
- 신청자를 개별 또는 복수 선택할 수 있으며 한 번에 최대 200명을 불러온다.
- 차단 사용자 명단은 최근 차단 순서로 표시한다.

신청자별로 다음 정보를 확인한다.

- 이름, 사용자 유형, 재입학 여부, 신청 시각
- 기수, 학번, 성별, 생일

### 16.2 가입 승인, 차단 및 해제

- 신청자를 개별 또는 복수로 승인하거나 차단하며, 한 번에 최대 200명의 신청을 처리한다.
- 승인된 사용자는 일반 서비스 기능을 이용할 수 있다.
- 차단된 사용자는 프로필을 수정하거나 다시 신청할 수 없다.
- 차단을 해제하면 사용자를 프로필 미작성 상태로 전환한다. 사용자는 학교 프로필 설정에서 정보를 수정한 뒤 다시 제출한다.
- 차단 사유는 입력하거나 표시하지 않는다.
- 승인, 차단 및 차단 해제 결과는 가입 이메일로 보내며 처리한 관리자의 신원과 차단 사유는 넣지 않는다. 같은 결과를 인앱 알림과 Web Push로도 전달하되 이메일을 대체하지 않는다.

### 16.3 앱 관리자 명단 보호

- 앱 관리자 명단과 권한 변경 화면을 열기 전에 현재 비밀번호로 본인을 다시 확인한다.
- 비밀번호 확인 후 5분 동안 관리자 명단 조회, 검색, 임명 및 강등을 허용한다.
- 관리자 명단에 이름, 프로필, 기수 또는 사용자 유형 및 부서를 표시하고, 현재 로그인한 관리자에게 `나` 표시를 제공한다.

### 16.4 관리자 후보 검색

- 승인된 사용자를 이름, 공개 프로필 ID 또는 기수로 검색한다.
- 검색어를 두 글자 이상 입력한 뒤 결과를 표시한다.
- 이름, 기수, 사용자 유형 및 부서를 함께 표시해 동명이인을 구분한다.

### 16.5 관리자 임명 및 강등

- 기존 앱 관리자는 승인된 사용자를 앱 관리자로 임명할 수 있다.
- 앱 관리자는 자신을 포함한 앱 관리자를 일반 사용자로 강등할 수 있으며, 마지막 한 명은 강등할 수 없다.
- 대상과 권한 변화를 두 단계로 확인한 뒤 적용한다.
- 앱 관리자 강등은 해당 사용자의 계정과 개별 그룹 역할에 영향을 주지 않는다.
- 임명 또는 강등 결과는 대상 사용자에게 높음 중요도로 알린다.

### 16.6 권한 기반 기능 관리자

- 승인된 사용자를 이름, 공개 프로필 ID 또는 기수로 검색한다.
- 승인된 사용자에게 공강 관리 권한을 부여하거나 회수한다.
- 공강 관리 권한 조회와 변경에는 앱 관리자 권한이 필요하지만 비밀번호 재확인은 요구하지 않는다.
- 권한 부여 또는 회수 결과는 대상 사용자에게 보통 중요도로 알린다.

### 16.7 파일 정리 상태

- 앱 관리자는 Storage 고아 파일 정리의 현재 상태를 확인한다. 조작하는 화면이 아니라 정리가 실제로 돌고 있는지 확인하는 화면이다.
- 화면 맨 위에 어떤 파일이 정리 대상인지 한 줄로 설명한다. 관리자가 다른 문서를 찾아보지 않고도 숫자의 단위를 알 수 있어야 한다.
- 그 아래에 "지금 괜찮은가"에 대한 종합 판정을 한 줄로 앞세우고, 그렇게 판정한 이유와 다음에 할 일을 함께 적는다. 판정은 화면이 이미 표시하는 값에서만 도출하며 새 임계값을 두지 않는다.
- 워커 설정(Vault 시크릿) 누락 여부를 표시한다. 설정이 없으면 정리가 한 건도 실행되지 않으므로 경고로 알리고, 종합 판정도 이 상태를 가장 우선해 반영한다.
- 삭제 대기 건수, 재시도 중인 건수, 스윕 후보 건수 및 가장 오래된 대기 항목의 시각을 표시한다.
- 재시도 건수는 대기 건수의 부분집합이므로 두 값이 더해지지 않는다는 것이 라벨에서 드러나야 한다.
- 스윕 후보는 아직 삭제하지 않은 상태로 표시해, 실제 삭제를 켜기 전에 후보를 확인할 수 있게 한다.
- 마지막 실행의 시작 시각, 응답 코드, 삭제 및 실패 건수, 오류 메시지와 마지막 예약 실행 결과를 표시한다. 이 숫자는 Storage 파일 단위이며 누적 합계가 아니라 최근 실행 한 번의 결과임을 화면에서 밝힌다.
- 삭제 건수에는 이미 사라져 지울 필요가 없던 파일이 포함된다. 두 경우를 구분해 표시하지는 않는다.
- 요청은 성공했지만 개별 파일을 지우지 못한 실행은 성공과 구분해 표시한다. 성공 표시 옆에 실패 건수가 서 있으면 어느 쪽이 실제 결과인지 알 수 없다.
- 상태 새로고침은 최신 요약을 다시 읽기만 하며, 정리 작업을 실행하거나 대기 항목을 변경하지 않는다.
- 정리 규칙 자체는 [Supabase Storage 버킷 설계](../STORAGE_BUCKETS.md) §8.2에 있다.

### 16.8 전체 인원

- 앱 관리자는 승인된 사용자 전체를 한 화면에서 본다. 대기·차단 사용자는 가입 승인 화면(§16.1)에서 본다.
- 앱 관리자 권한만 확인하며 비밀번호 재확인은 요구하지 않는다.
- 이름, 공개 프로필 ID, 사용자 유형, 기수, 부서와 앱 관리자 여부만 표시한다. 학번·연락처 등 가입 신청 정보는 표시하지 않는다.
- 사용자 유형(학생·졸업생·교직원)별 인원 수를 보여 주고 유형으로 거른다. 학생·졸업생은 고른 유형 안의 기수별 인원 수를 보여 주고 기수로 다시 거른다. 기수가 없는 교직원은 기수로 거르지 않는다.
- 이름, 공개 프로필 ID 또는 부서로 검색하고 이름순, 최신 기수순, 최근 승인순으로 정렬한다.
- 지금 걸러진 목록을 CSV로 내려받는다. 표시하는 항목에 승인 시각을 더한다.

### 16.9 관리자 연락처

앱을 쓰지 못하는 사람(로그인 전, 승인 대기, 가입 차단)이 관리자에게 연락할 수 있도록 앱 관리자가 연락처를 등록한다.

- 앱 관리자는 `/admin/contacts`에서 연락처를 추가, 수정, 삭제하고 순서를 바꾼 뒤 목록 전체를 한 번에 저장한다. 앱 관리자 권한만 확인하며 비밀번호 재확인은 요구하지 않는다.
- 연락처는 종류(링크 또는 이메일), 이름(40자 이내), 주소로 이루어지며 최대 10개까지 둔다. 링크는 `https://` 주소만 받는다.
- 막힌 사람만 찾아 누르도록 눈에 띄지 않게 둔다. 화면 아래에 상황을 묻는 작은 글자 하나만 두고, 누르면 저장한 순서대로 연락처를 펼친다. 링크는 새 탭으로, 이메일은 메일 앱으로 연다.

  | 화면      | 보이는 때          | 문구                       |
  | --------- | ------------------ | -------------------------- |
  | 로그인    | 로그인에 실패한 뒤 | 계속 로그인이 안 되나요?   |
  | 회원가입  | 이메일 인증 단계   | 인증 메일이 오지 않나요?   |
  | 승인 대기 | 항상               | 승인이 너무 오래 걸리나요? |
  | 가입 차단 | 항상               | 차단이 잘못된 것 같나요?   |

- 등록된 연락처가 없거나 불러오지 못하면 문의 영역을 표시하지 않으며, 연락처를 불러오는 동안에도 화면의 나머지는 먼저 표시한다.
- 로그인하지 않은 사람도 볼 수 있는 공개 정보다. 관리 화면에 개인 연락처 대신 공용 연락처를 쓰라고 안내한다.
- 도움말(§15.11)의 문의 영역과는 별개다.

### 16.10 학교 공지 계정

- 앱 관리자는 `/admin/school-notices`에서 학교 공지(§17.10) 동기화에 쓰는 학교 계정을 바꾸고 동기화 상태를 본다. 학교가 허락한 공지 열람용 계정을 쓴다.
- 학교 아이디는 누구 계정인지 알 수 있도록 화면에 보여준다. 비밀번호는 입력만 받고 저장한 값을 어떤 화면이나 응답에도 돌려주지 않는다. 아이디와 비밀번호는 Vault에만 저장하고 로그에 남기지 않는다.
- 계정을 저장하면 바로 한 번 동기화를 요청한다. 관리자는 "지금 동기화"로 언제든 다시 요청할 수 있다.
- 상태 화면은 학교 아이디, 마지막 성공 시각, 보관 중인 공지 수, 마지막 실패 시각과 이유를 보여준다. 동기화 설정이 없거나, 요청 후 5분이 지나도 함수가 결과를 기록하지 않으면 경고한다.
