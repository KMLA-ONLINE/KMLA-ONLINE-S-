# 알림 수동 인수 테스트

자동화 테스트만으로 확인하기 어려운 부분은 실제 브라우저, 운영체제, 설치형 PWA, 실제 Push Service와 이메일 제공자를 거치는 동작이다. 다음 체크리스트를 알림 기능의 수동 인수 테스트로 사용한다.

## 테스트 환경

최소 지원 환경을 먼저 확정하고 각각 테스트해야 한다.

- 데스크톱 Chrome
- 데스크톱 Safari
- Android Chrome
- iPhone 설치형 PWA
- iPad 설치형 PWA
- 실제 HTTPS 스테이징 환경
- 실제 수신 가능한 이메일 계정
- 사용자 계정 3개 이상
- 일반 사용자, 그룹 운영자, 앱 관리자 계정
- 두 대 이상의 실제 기기

iOS/iPadOS는 홈 화면에 설치하지 않은 일반 Safari 탭과 설치형 PWA를 별도로 확인해야 한다.

## 권한 요청

- [ ] 가입 승인 후 첫 진입에서 브라우저 권한 창보다 자체 안내가 먼저 표시된다.
- [ ] 자체 안내를 닫아도 앱을 정상적으로 사용할 수 있다.
- [ ] 자체 안내를 닫은 뒤 페이지를 이동하거나 새로고침해도 즉시 다시 나타나지 않는다.
- [ ] `알림 받기`를 누른 경우에만 브라우저 권한 창이 표시된다.
- [ ] 권한을 허용하면 알림 설정이 활성 상태로 바뀐다.
- [ ] 권한을 거절해도 앱 이용을 막지 않는다.
- [ ] 권한 거절 후 브라우저 권한 창을 반복해서 요청하지 않는다.
- [ ] 거절 상태에서 브라우저 설정 변경 방법을 안내한다.
- [ ] 브라우저 설정에서 권한을 허용한 후 앱이 상태를 올바르게 다시 인식한다.
- [ ] 브라우저 설정에서 권한을 취소하면 앱이 더 이상 Push 활성 상태로 표시하지 않는다.
- [ ] Push API를 지원하지 않는 환경에서 켜기 버튼 대신 지원 불가 안내가 표시된다.
- [ ] iOS에서 설치하지 않은 Safari와 설치형 PWA에 적절히 다른 안내가 표시된다.

## 기본 설정

- [ ] 처음 Push를 켜면 보통·높음 중요도 유형이 기본 활성화된다.
- [ ] 반응 등 낮음 중요도 Push는 기본 비활성화된다.
- [ ] 알림 설정 화면과 실제 브라우저 권한 상태가 일치한다.
- [ ] 브라우저 권한은 허용됐지만 앱의 Web Push 전체 설정을 끄면 Push가 오지 않는다.
- [ ] 전체 설정을 다시 켜면 새로운 Push가 정상 수신된다.
- [ ] 설정 변경 직전에 만들어졌지만 아직 발송되지 않은 알림에도 최신 설정이 적용된다.

## 중요도 정책

### 낮음

- [ ] 게시물 반응은 인앱 알림함에 표시된다.
- [ ] 댓글 반응은 인앱 알림함에 표시된다.
- [ ] 게시물·댓글 반응은 Web Push로 오지 않는다.
- [ ] 메시지 반응은 대화 안에 표시되지만 Web Push로 오지 않는다.
- [ ] 새 그룹 게시물은 인앱에 표시된다.
- [ ] 그룹별 새 게시물 Push를 직접 켜기 전에는 Push로 오지 않는다.
- [ ] 해당 그룹에서 직접 켠 후에는 새 게시물 Push가 온다.

### 보통

- [ ] 댓글, 답글, 멘션은 기본 설정에서 Push로 온다.
- [ ] 타임라인 활동은 기본 설정에서 Push로 온다.
- [ ] 그룹 가입 승인·거절 및 역할 변경은 기본 설정에서 Push로 온다.
- [ ] 유형별 opt-out 이후 해당 유형만 Push가 중단된다.
- [ ] opt-out해도 인앱 알림은 계속 생성된다.
- [ ] 그룹 알림을 `없음`으로 바꾸면 해당 그룹의 일반 콘텐츠 Push가 중단된다.
- [ ] 그룹 콘텐츠 설정을 꺼도 가입 요청 결과나 역할 변경 같은 그룹 상태 알림은 별도 유형 설정에 따라 전달된다.
- [ ] 대화 알림을 끄면 해당 대화의 Push만 중단된다.
- [ ] 대화를 일정 시간 음소거하면 만료 전에는 오지 않고 만료 후 다시 온다.

### 높음과 운영 조치

- [ ] 익명 제한 알림은 인앱에 항상 생성된다.
- [ ] 운영자에 의한 게시물·댓글 삭제 알림은 인앱에 항상 생성된다.
- [ ] 댓글 유형 또는 그룹 알림을 꺼도 운영 조치 Push는 온다.
- [ ] Web Push 전체 설정을 끄면 운영 조치도 Push로 오지 않는다.
- [ ] OS 권한을 거절하면 운영 조치도 Push로 오지 않는다.
- [ ] 이미 적용 중인 익명 제한을 다시 적용해도 알림이 반복되지 않는다.
- [ ] 익명 제한 만료 또는 수동 해제 시 별도 알림이 생성되지 않는다.
- [ ] 그룹 소유권 이전과 그룹 삭제가 높음 중요도로 전달된다.

## 중복 방지

- [ ] 자신의 게시물에 자신이 댓글을 달아도 자기 알림이 생기지 않는다.
- [ ] 자신의 댓글에 자신이 반응해도 자기 알림이 생기지 않는다.
- [ ] 게시물 작성자와 부모 댓글 작성자가 같은 경우 답글 알림 하나만 생긴다.
- [ ] 댓글 수신자와 멘션 대상이 같으면 별도 알림 두 개가 생기지 않는다.
- [ ] 같은 멘션을 제거한 뒤 다시 추가해도 Push가 반복되지 않는다.
- [ ] 한 사용자가 반응 종류를 여러 번 바꿔도 새 알림이 반복되지 않는다.
- [ ] 반응을 취소해도 새 알림이 생기지 않는다.
- [ ] 여러 사용자의 반응이 하나의 인앱 알림으로 적절히 집계된다.
- [ ] 소유권 이전 시 역할 변경과 소유권 이전 Push가 중복되지 않는다.
- [ ] 같은 이벤트를 재시도해도 같은 Push가 두 번 표시되지 않는다.

## 신원과 개인정보

- [ ] 실명 활동은 올바른 이름과 프로필 사진을 표시한다.
- [ ] 익명 게시물·댓글·반응은 실제 신원을 Push에 노출하지 않는다.
- [ ] 운영진 명의 활동은 `운영진`으로 표시한다.
- [ ] 탈퇴 사용자는 `탈퇴한 사용자`로 표시한다.
- [ ] 운영 조치를 수행한 운영자 신원이 표시되지 않는다.
- [ ] 삭제된 댓글과 게시물 원문이 Push 본문에 포함되지 않는다.
- [ ] 내부 UUID, 프로필 ID, endpoint 등의 내부 값이 표시되지 않는다.
- [ ] 잠금 화면에서도 민감한 정보가 노출되지 않는다.
- [ ] 비공개 개인 게시물에서는 콘텐츠 알림이나 Push가 생성되지 않는다.
- [ ] 접근할 수 없는 그룹이나 콘텐츠의 정보가 Push로 유출되지 않는다.
- [ ] 메시지 Push에 암호화된 메시지 평문과 첨부 파일명이 표시되지 않는다.
- [ ] 메시지 Push는 발신자와 새 메시지가 있다는 일반 안내만 표시한다.

## 앱 상태별 수신

같은 Push를 다음 상태에서 각각 확인해야 한다.

- [ ] 앱 탭이 화면에 열려 있는 상태
- [ ] 앱 탭이 백그라운드에 있는 상태
- [ ] 브라우저 창이 닫힌 상태
- [ ] 설치형 PWA가 완전히 종료된 상태
- [ ] 기기 화면이 잠긴 상태
- [ ] 기기가 오프라인인 상태
- [ ] 오프라인 이후 다시 연결된 상태
- [ ] 절전 또는 저전력 모드
- [ ] 브라우저를 강제 종료한 이후
- [ ] 기기를 재부팅한 이후

확인할 항목:

- [ ] 시스템 알림이 한 번만 표시된다.
- [ ] 제목, 본문, 아이콘이 운영체제별로 읽을 수 있다.
- [ ] 한글이 잘리더라도 의미를 이해할 수 있다.
- [ ] 오래 지연된 Push가 현재 상태와 모순되는 문구를 표시하지 않는다.
- [ ] 동일 유형이 짧은 시간에 여러 번 발생해도 알림이 과도하게 쌓이지 않는다.

## Push 클릭과 이동

- [ ] 앱이 닫혀 있을 때 알림을 누르면 PWA 또는 브라우저가 열린다.
- [ ] 이미 앱 탭이 있으면 새 탭을 불필요하게 만들지 않고 기존 탭을 사용한다.
- [ ] 다른 화면을 보고 있던 기존 탭이 정확한 대상 화면으로 이동한다.
- [ ] 알림 클릭 후 해당 인앱 알림이 읽음 처리된다.
- [ ] 이미 읽은 Push를 클릭해도 대상 화면으로 정상 이동한다.
- [ ] 로그아웃 상태에서 클릭하면 로그인 후 원래 목적지로 이동한다.
- [ ] 다른 계정으로 로그인된 상태에서 타인의 알림 대상을 노출하지 않는다.
- [ ] 대상 게시물이 삭제된 경우 안전한 안내를 표시한다.
- [ ] 그룹 탈퇴 등으로 접근 권한을 잃은 경우 내용을 노출하지 않는다.
- [ ] 잘못되거나 조작된 외부 URL을 열지 않는다.
- [ ] 여러 알림 중 하나를 눌러도 정확한 게시물·댓글·그룹으로 이동한다.

## 여러 기기와 계정

- [ ] 한 계정이 두 기기에서 Push를 켜면 두 기기 모두 수신한다.
- [ ] 한 기기에서 Push를 꺼도 다른 기기의 구독은 유지된다.
- [ ] 한 기기의 권한을 철회해도 다른 기기에는 정상 전송된다.
- [ ] 로그아웃 후 이전 사용자의 Push가 해당 기기에 오지 않는다.
- [ ] 공용 기기에서 다른 계정으로 로그인해도 이전 계정의 Push가 오지 않는다.
- [ ] 같은 브라우저에서 계정을 전환하면 현재 계정의 알림만 온다.
- [ ] 브라우저 데이터 삭제 후 오래된 구독이 사용자에게 계속 활성 기기로 표시되지 않는다.
- [ ] 앱 삭제 후 재설치 또는 PWA 제거 후 재설치 시 구독 상태가 정상적으로 복구된다.

## 서비스 워커 업데이트

- [ ] 서비스 워커 업데이트 대기 중에도 기존 Push가 수신된다.
- [ ] 사용자가 앱 업데이트를 수락한 뒤에도 기존 구독이 유지된다.
- [ ] 새 서비스 워커 활성화 직전과 직후에 Push가 중복 표시되지 않는다.
- [ ] 오래된 앱 탭과 새 앱 탭이 동시에 있어도 Push가 중복되지 않는다.
- [ ] 업데이트된 서비스 워커에서 알림 클릭 경로가 정상 작동한다.
- [ ] 오프라인 캐시 업데이트 기능과 Push 이벤트 처리가 서로 방해하지 않는다.

## 알림함 동기화

- [ ] Push가 도착한 뒤 앱을 열면 같은 인앱 알림이 존재한다.
- [ ] Push 발송에 실패해도 인앱 알림은 존재한다.
- [ ] Push를 클릭하지 않고 앱에서 읽으면 읽음 상태가 올바르게 반영된다.
- [ ] 다른 기기에서 읽음 처리한 결과가 현재 기기에 반영된다.
- [ ] 모두 읽음 처리 후 배지가 사라진다.
- [ ] 최근 24시간과 이전 알림 구분이 실제 시간대에서 정확하다.
- [ ] 30일이 지난 알림이 제거된다.
- [ ] 연결 대상이 영구 삭제된 알림을 열 때 오류가 발생하지 않는다.

시간 경계 테스트는 기기 시간 변경만 믿지 말고 스테이징 테스트 데이터의 생성 시각을 조정해서 확인하는 것이 안전하다.

## 메시지 전용

- [ ] 일반 알림함 배지와 메시지 unread 배지가 독립적으로 움직인다.
- [ ] 메시지 Push를 눌렀을 때 정확한 대화로 이동한다.
- [ ] 답장은 새 메시지 Push 하나로만 표시된다.
- [ ] `모든 메시지` 설정에서 일반 그룹 메시지가 Push로 온다.
- [ ] `멘션 중심` 설정에서 일반 메시지는 오지 않고 멘션만 온다.
- [ ] 음소거 중에도 unread 수는 증가한다.
- [ ] 새 그룹 멤버에게 가입 이전 메시지 정보가 Push로 노출되지 않는다.
- [ ] 그룹에서 내보내진 사용자가 이후 메시지 Push를 받지 않는다.
- [ ] 그룹에서 내보내졌다는 높음 중요도 알림은 정상적으로 받는다.

## 이메일

실제 메일 제공자를 통과하는 테스트가 필요하다.

- [ ] 가입 승인 이메일이 실제 받은편지함에 도착한다.
- [ ] 가입 차단 이메일이 도착한다.
- [ ] 차단 해제 이메일이 도착한다.
- [ ] 비밀번호 변경·초기화 보안 이메일이 도착한다.
- [ ] 계정 탈퇴 완료 이메일이 도착한다.
- [ ] 차단 해제 이메일에 프로필 수정 및 재제출 안내가 있다.
- [ ] 관리자 신원이 이메일에 포함되지 않는다.
- [ ] 차단 사유가 이메일에 포함되지 않는다.
- [ ] 수신자 이름과 서비스 URL이 정확하다.
- [ ] 링크가 HTTPS 운영 도메인을 사용한다.
- [ ] Gmail, Outlook, 네이버 등 주요 메일함에서 깨지지 않는다.
- [ ] 다크 모드에서도 읽을 수 있다.
- [ ] 스팸함 분류 여부와 SPF·DKIM·DMARC 결과를 확인한다.
- [ ] 동일 상태 처리의 재시도로 이메일이 중복 발송되지 않는다.

## 학교 기능

- [ ] 관리자 선예약으로 장기 예약이 종료되면 기존 예약자에게 높음 알림이 온다.
- [ ] 알림에 영향받은 날짜, 장소, 시간대를 정확히 표시한다.
- [ ] 예약을 종료한 관리자의 신원을 노출하지 않는다.
- [ ] 예약 리마인더를 켠 사용자에게만 알림이 온다.
- [ ] 리마인더를 끄면 인앱 또는 Push 정책이 명세와 일치한다.
- [ ] 노래방 예약 알림이 참여자 외 사용자에게 가지 않는다.
- [ ] 모집 시작·마감 알림을 직접 켠 사용자에게만 전달한다.

## 접근성 및 사용성

- [ ] 자체 권한 안내를 키보드만으로 조작할 수 있다.
- [ ] 스크린 리더가 권한 상태와 버튼 목적을 이해할 수 있게 읽는다.
- [ ] 권한 거절 안내가 사용자를 비난하거나 기능 이용을 강요하지 않는다.
- [ ] 모바일에서 안전 영역과 시스템 UI에 가리지 않는다.
- [ ] 알림 설정 변경 결과가 즉시 이해할 수 있게 표시된다.
- [ ] 운영 조치 알림을 끌 수 없는 이유를 명확하게 안내한다.
- [ ] 알림이 연속으로 도착해도 앱 사용을 방해하는 모달을 반복 표시하지 않는다.

## 출시 전 필수 시나리오

전체 체크리스트와 별도로 매 출시마다 다음 스모크 테스트를 반드시 수행한다.

1. Android Chrome에서 권한 허용, 댓글 Push 수신, 클릭 이동
2. iPhone 설치형 PWA에서 Push 수신과 클릭 이동
3. 댓글 Push opt-out 후 인앱만 생성되는지 확인
4. 반응이 인앱에만 표시되는지 확인
5. 운영 조치가 콘텐츠 opt-out을 무시하는지 확인
6. Web Push 전체 비활성화가 운영 조치에도 적용되는지 확인
7. 로그아웃과 계정 전환 후 이전 사용자 Push가 오지 않는지 확인
8. 두 기기에서 같은 계정이 정상 수신하는지 확인
9. 삭제되거나 접근 권한을 잃은 대상의 Push 클릭 처리
10. 가입 승인·차단·해제 실제 이메일 수신
11. 메시지 Push에 평문이 노출되지 않는지 확인
12. 서비스 워커 업데이트 이후 구독이 유지되는지 확인

각 실행에서 환경, 테스터, 실행일, 결과 및 증거 링크를 기록한다.
