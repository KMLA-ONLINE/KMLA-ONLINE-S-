# 콘텐츠 서식 및 이모지 설계

## 1. 문서 목적

이 문서는 게시물 본문과 메시지의 저장 형식과 편집 방식, 안전한 출력 규칙 및 Unicode 이모지 처리 방식을 정의한다. 기능 요구사항은 도메인별 기능 명세를 따르며 이 문서는 구현 경계와 호환성 규칙을 다룬다.

## 2. 게시물 저장 형식

- 게시물 본문의 기준 형식은 `Markdown v1`이다.
- 데이터베이스에는 HTML이나 편집기 전용 JSON이 아닌 Markdown 원문을 저장한다.
- 본문 20,000자 제한은 저장되는 Markdown 원문의 PostgreSQL `char_length`를 기준으로 한다.
- 본문 형식 버전은 게시물 행에 저장해 이후 문법 변경 시 기존 본문의 렌더링을 유지한다.
- 제목과 본문으로 생성하는 검색 문자열은 현재 Markdown 원문을 사용한다. 목록의 평문 요약은 Markdown 문서 트리에서 텍스트를 추출해 만든다.

## 3. Markdown v1

### 3.1 허용 서식

| 기능          | 저장 문법                       |
| ------------- | ------------------------------- |
| 문단과 줄바꿈 | CommonMark 문단과 줄바꿈        |
| 굵게          | `**텍스트**`                    |
| 기울임        | `*텍스트*`                      |
| 취소선        | `~~텍스트~~`                    |
| 큰 제목       | `## 제목`                       |
| 작은 제목     | `### 제목`                      |
| 링크          | `[텍스트](https://example.com)` |

게시물 제목이 문서의 최상위 제목이므로 본문에서 1단계 제목은 사용하지 않는다.

### 3.2 지원하지 않는 서식

- 밑줄
- 작성자 지정 글꼴
- 임의 글자 크기
- 글자색과 배경색
- 표와 체크리스트
- 인라인 코드와 코드 블록
- Markdown 이미지
- 원시 HTML

지원하지 않는 붙여넣기 서식은 제거하고 텍스트 또는 가장 가까운 허용 서식으로 변환한다. 게시물 이미지는 Markdown이 아니라 게시물 첨부로 관리한다.

## 4. 게시물 편집기

### 4.1 데스크톱

- Markdown을 기준 형식으로 사용하는 Milkdown 기반 WYSIWYG 편집기를 사용한다.
- 굵게, 기울임, 취소선, 제목 등은 편집 영역에서 즉시 표시한다.
- 편집기 툴바와 키보드 단축키는 기능 명세에 정의된 서식만 제공한다.
- 별도 미리보기 모드를 제공하지 않는다.
- 편집기와 읽기 전용 본문 출력은 같은 타이포그래피 토큰과 간격 규칙을 사용한다.
- 링크를 일반 클릭하면 편집 위치를 선택하고 `Ctrl/Cmd+클릭`하면 새 탭에서 연다.
- 한글 IME 조합 중인 키 입력을 단축키나 제출 동작으로 처리하지 않는다.

### 4.2 모바일

- 네이티브 `textarea` 기반의 일반 본문 입력을 제공한다.
- 서식 툴바와 서식 단축키를 제공하지 않는다.
- 기존 서식 게시물을 수정할 때는 Markdown 원문을 표시한다.
- 모바일에서도 사진 및 파일 첨부와 게시물의 나머지 입력 항목은 모두 사용할 수 있다.

## 5. 메시지 입력기

### 5.1 기준 형식

- 메시지 본문의 기준 형식은 Unicode 평문이다.
- Markdown, HTML, 편집기 JSON 및 이미지 정보는 메시지 본문에 저장하지 않는다.
- 메시지 본문을 암호화하기 직전에 편집기 내용을 원래 Unicode 평문으로 직렬화하고 마지막 글자 뒤의 연속 줄바꿈을 제거한다.
- 수신하거나 수정할 메시지는 복호화한 Unicode 평문으로 입력기 상태를 다시 만든다.
- 메시지 복사, 전달 및 세션 내 검색도 같은 Unicode 평문을 사용한다.

### 5.2 편집 모델

- 데스크톱과 모바일에서 Lexical 기반 plain-text 입력기를 사용한다.
- 편집기 문서는 텍스트, 줄바꿈 및 이모지 노드만 허용한다.
- 이모지는 별도 이미지 노드로 변환하지 않고 Unicode 텍스트로 다룬다.
- 입력 순서와 본문 중간의 줄바꿈은 전송된 메시지와 같게 유지한다.
- URL은 입력 중 일반 텍스트로 표시하고 읽기 전용 메시지에서만 링크로 변환한다.
- 이모지만 있는 메시지의 확대는 전송된 읽기 전용 메시지에만 적용한다.
- 붙여넣기는 HTML과 글자 서식을 제거하고 평문과 줄바꿈만 유지한다.
- 한글 IME 등 텍스트 조합이 끝난 뒤 이모지 노드 변환과 전송 단축키를 처리한다.

### 5.3 길이와 암호화 경계

- 메시지 5,000자 제한은 `Intl.Segmenter`의 grapheme cluster 기준으로 클라이언트에서 검사한다.
- 데이터베이스와 일반 API는 암호화된 본문의 실제 글자 수를 확인할 수 없으므로 암호문 바이트 상한으로 저장량을 제한한다.
- 수신 클라이언트는 복호화한 본문의 글자 수를 다시 검사하고 제한을 위반한 본문을 정상 메시지로 렌더링하지 않는다.
- 편집한 메시지는 새 nonce로 다시 암호화하며 편집기 내부 상태를 암호문에 포함하지 않는다.

## 6. 읽기 전용 렌더링

### 6.1 게시물

- 유지보수되는 Markdown 파서로 문서 트리를 만든 뒤 허용된 React 요소만 출력한다.
- 정규식으로 HTML 문자열을 조합하거나 `dangerouslySetInnerHTML`에 의존하지 않는다.
- 원시 HTML은 실행하거나 DOM으로 삽입하지 않는다.
- 링크는 `http`와 `https` 프로토콜만 허용한다.
- 외부 링크는 새 탭에서 열고 `noopener noreferrer`를 적용한다.
- 피드 카드, 게시물 상세 및 편집기의 타이포그래피는 같은 스타일 정의를 사용한다.
- 피드의 접힌 본문과 검색 결과 요약은 Markdown 문법이 아닌 평문을 표시한다.

### 6.2 메시지

- 복호화한 Unicode 평문을 Markdown이나 HTML로 해석하지 않는다.
- 줄바꿈, HTTP(S) URL 및 이모지를 식별해 허용된 React 요소로만 출력한다.
- URL 이외의 텍스트와 공백은 입력된 순서대로 유지한다.
- URL은 입력기에서는 일반 텍스트로 두고 읽기 전용 메시지에서만 링크로 만든다.
- 메시지를 복사할 때는 링크 요소가 아닌 원래 Unicode 평문을 사용한다.

## 7. 이모지

### 7.1 저장과 변환

- 데이터베이스와 Markdown에는 사용자가 입력한 Unicode 이모지를 그대로 저장한다.
- shortcode, 이모지 이미지 URL, SVG 또는 이미지 HTML을 본문에 저장하지 않는다.
- 게시물과 메시지의 입력기 및 읽기 전용 콘텐츠에서는 기기의 기본 Unicode 이모지를 표시한다.
- 복사와 검색에는 원래 Unicode 이모지를 사용한다.

### 7.2 반응

- 반응은 우선 Unicode 이모지를 사용한다.
- 반응에 통일된 그래픽이 필요해지면 일반 콘텐츠 렌더링과 분리된 범위로 별도 설계한다.

## 8. 보안 및 접근성

- Markdown 입력은 신뢰하지 않으며 출력 허용 목록을 보안 경계로 사용한다.
- 사용자 입력 URL은 허용 프로토콜을 검사하고 이벤트 속성이나 스크립트를 출력하지 않는다.
- 툴바 버튼은 텍스트 이름, 눌림 상태 및 해당하는 `aria-keyshortcuts`를 제공한다.
- 키보드만으로 서식을 적용하고 편집기로 돌아갈 수 있어야 한다.
- 움직임이 필요한 편집기 피드백은 `prefers-reduced-motion`을 따른다.

## 9. 검증 범위

- Markdown 저장과 파싱의 왕복 변환
- 중첩된 굵게, 기울임 및 취소선
- 허용하지 않은 HTML, URL 프로토콜 및 붙여넣기 서식 제거
- 데스크톱 단축키와 실행 취소 및 다시 실행
- 한글 IME 조합과 모바일 `textarea` 입력
- 메시지 평문 직렬화, 후행 줄바꿈 제거, 본문 중간 줄바꿈 유지, 붙여넣기 및 5,000 grapheme 제한
- 메시지 입력기와 읽기 전용 출력 사이의 텍스트 및 이모지 순서 일치
- 게시물과 메시지에서 복합 이모지, 피부색, 국기 및 ZWJ 시퀀스의 Unicode 유지
