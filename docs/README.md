## 기술 설계와 정책

- [홈 통합 피드](FEED_ALGORITHM.md): 후보·랭킹·출처 제한·세션과 페이지네이션
- [콘텐츠 서식](CONTENT_FORMATTING.md): 저장 형식·편집기·안전한 렌더링·이모지
- [클라이언트 캐시](DATA_CACHE_POLICY.md): 쿼리 키·신선도·무효화·기기 저장소
- [Storage 버킷](STORAGE_BUCKETS.md): 파일 정책·접근 권한·업로드·object 정리
- [삭제 및 보존](DELETION_POLICY.md): DB 행 수명·보존 기간·정리 작업
- [알림 및 Web Push](NOTIFICATION_TECHNICAL_DESIGN.md): 데이터·outbox·worker·클라이언트 동기화

메시지는 화면 골격만 제공한다. 메시지 명세와 관련 기술 설계의 미구현 표시는 현재 제공 기능과
도입 시 규칙을 구분한다. 상세한 미래 설계가 존재한다고 구현된 기능인 것은 아니다.

## 문서 책임과 추가 위치

| 문서                              | 소유하는 정보                                                      |
| --------------------------------- | ------------------------------------------------------------------ |
| 루트 README                       | 실행에 필요한 최소 절차·환경 변수·릴리스 진입점                    |
| `functional-spec/`                | 사용자 관점의 제품 요구·권한·동작                                  |
| `structure.md`와 기술 설계        | 코드 배치·구현 경계·불변식과 설계 근거                             |
| `DOCKER.md`, `supabase/README.md` | 환경 설정과 DB 작업의 실행 절차                                    |
| `AGENT_MAP.md`                    | 코드·테스트·DB 좌표. 자동 검사 범위는 파일 머리말 참조             |
| 루트와 feature의 AGENTS.md        | 작업 규칙과 실패를 막는 로컬 불변식                                |
| 구현 기록                         | 완료된 변경의 배경. 현재 정책이나 미완료 작업으로 읽지 않도록 구분 |

- 새 제품 요구는 기존 도메인 명세에 추가한다. 기술 설계는 관련 문서를 먼저 확장하고, 독립된
  책임이 생겼을 때만 새 파일을 만든다. 새 문서는 이 안내와 필요한 관련 문서에서 연결한다.
- 프로젝트 문서는 현재 디렉터리를 우선 사용한다. DB 작업은 `supabase/README.md`, 기능 로컬
  불변식은 해당 feature의 AGENTS.md에 둔다. 같은 명령·상수·정책을 여러 곳에 복사하기보다
  정본과 실제 구현·테스트를 링크한다.
- 변경된 동작·구조는 코드와 문서를 같은 변경에서 맞춘다. 새 문서는 목적과 범위를 먼저 적고,
  명령은 저장소의 npm script나 설치된 CLI를 사용한다.
- 미구현 내용은 장이나 절 제목 바로 아래 `> **상태**: 미구현`으로 표시한다. 장 전체가 미구현이면
  하위 절이 그 상태를 따른다. 부분 구현은 제공 범위와 미래 규칙을 구분한다. 의도적으로 제공하지
  않는 기능은 미완료 작업이 아닌 결정으로 적는다.
- 명세의 절 번호는 안정적인 식별자다. 추가·변경은 [장 번호 규칙](KMLA_SPEC_INDEX.md#장-번호-규칙)을 따른다.
- 과거 기록은 명시적인 구현 기록 절에 둔다. 길어져 현재 정책을 가릴 때만 아카이빙을 검토하고,
  출처·현재 정본 링크를 남긴다. ADR은 독립적으로 추적할 중요한 결정이 생길 때만 도입한다.
- `assets/`의 자산은 연결 문서와 용도를 명시한다. 기존 설치 안내 영상은 사용 의도가 확인되지
  않아 보존하며, 현재 앱에 연결된 안내로 취급하지 않는다.

## 문서 검증

`npm run check`는 코드 지도와 프로젝트 문서의 로컬 링크·Markdown 제목 앵커를 검사한다.
외부 URL의 응답, 원격 환경 설정, 요구사항의 실제 구현 여부는 자동 링크 검사로 보장하지 않는다.
코드 예시와 inline code는 링크로 검사하지 않는다. 에이전트 skill 자료는 이 프로젝트 문서 검사의
대상이 아니다.
