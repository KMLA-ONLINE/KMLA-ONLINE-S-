# 클라이언트 데이터 캐시 정책

Supabase 조회 캐시와 무효화 규칙을 정한다. 데이터와 권한의 기준은 언제나 DB와 RLS이고, 클라이언트 캐시는 속도를 위한 수단일 뿐 권한 검사가 아니다.

## 1. 기본 원칙

- 서버 조회 캐시는 TanStack Query의 메모리 캐시만 쓴다. 보호된 조회 결과와 signed URL을
  `localStorage`, IndexedDB, Cache Storage에 저장하지 않는다.
- 예외는 Storage 이미지 본문 하나다. Service Worker가 `kmla-online-storage-media`에 담으며, 규칙과
  이유는 `scripts/build-sw.mjs`에 있다. 지켜야 할 경계만 적는다.
  - 키는 토큰을 뗀 object 경로다. 토큰은 저장하지 않는다.
  - `<img>` 요청(`request.destination === "image"`)의 200 이미지 응답만, 1MiB 이하만, 24시간까지만
    담는다. opaque 응답은 담지 않으므로 Storage 이미지 `<img>`에는 `crossOrigin="anonymous"`를 단다.
  - 저장소 주인이 바뀌면 계정 키(§7)와 같은 시점에 통째로 지운다. 캐시 이름이 앱과 빌드 스크립트에서
    어긋나면 빌드가 실패한다.
- 로그인 사용자 ID가 바뀌거나 로그아웃하면 QueryClient 전체를 비운다.
- 쿼리 키는 기능별 팩토리(`data/cache.ts`)에서만 만든다.
- mutation은 영향을 주는 목록과 상세를 명시적으로 무효화한다.
- 에러 응답, 권한 거부, 초대·관리자 데이터는 오래 캐시하지 않는다.

## 2. 키 구조

키의 첫 항목은 기능 영역, 다음은 조회 종류다. 검색어는 정규화한 값을, 페이지 커서는 키에 넣는다.
기능 루트 키(`["feed"]`, `["groups"]`)는 하위 전체를 stale 처리할 때만 쓰고, 일반 mutation은 가장
좁은 키를 무효화한다.

## 3. 신선도와 보관 시간

| 데이터                   | staleTime | 이유                                                                                                                          |
| ------------------------ | --------: | ----------------------------------------------------------------------------------------------------------------------------- |
| 피드 세션                |      15초 | 같은 tick의 중복 요청만 막는다. 갱신 시점은 §4.                                                                               |
| 스토리 레일              |       2분 | 앱 왕복 복귀마다 다시 받지 않는다.                                                                                            |
| 그룹 홈·탐색·상세·게시물 |       2분 | 앱 왕복 복귀마다 다시 받지 않는다. 내 변경은 §4가 덮는다.                                                                     |
| 멤버·가입 요청·신고·초대 |       0초 | 권한과 운영 상태에 민감하다.                                                                                                  |
| 알림함·알림 설정         |       0초 | Realtime과 focus 복귀가 재검증한다.                                                                                           |
| 셸 알림 뱃지             |       1분 | observer가 셸 전환마다 다시 마운트된다. 게이트는 항상 새로 읽는다.                                                            |
| 전역 검색 결과           |       0초 | 매 검색이 명시적 제출이다.                                                                                                    |
| 그룹 게시물 검색 결과    |       2분 | 결과에서 연 게시물을 닫고 돌아오면 같은 검색을 다시 돌리지 않는다. 그룹 게시물 목록 키 아래에 있어 목록 무효화가 함께 덮는다. |
| 그 밖의 영역             |       0초 | 따로 검토하기 전에는 진입마다 새로 읽는다.                                                                                    |

- 기본 `gcTime`은 10분이다. signed URL은 1시간짜리를 발급해 `staleTime`·`gcTime` 모두 55분 동안
  재사용하고, 키에 `userId`를 넣는다.
- 그룹 홈과 스토리 레일은 화면이 캐시를 `useQuery`로 구독한다. 로더는 캐시가 있으면 오래됐어도
  기다리지 않고 넘기고, 다시 읽기는 화면이 뒤에서 한다. 그룹 홈은 무효화된 캐시만은 새로 받을 때까지
  기다린다. 내가 방금 바꾼 것이 되돌아간 것처럼 보이지 않게 하기 위해서다.
- 그룹 게시물 목록을 열면 그룹 홈 캐시의 그 그룹 새 글 수를 먼저 0으로 낮추고 방문을 기록한다
  (기능 명세 §7.19). 기록이 실패했을 때만 그룹 홈을 무효화한다.

## 4. 무효화 규칙

### 피드

피드는 `["feed", "list"]` 하나의 무한 쿼리에 세션 단위로 담는다. 페이지 토큰이 첫 페이지의
`feedEpoch`에 묶여 있어서 무효화(쌓인 페이지 전부 다시 읽기) 대신 `resetFeed`로 새 세션의 첫 페이지를
연다. 시간 기반 자동 갱신은 끈다. 새 세션은 서버에서 비싸므로 아래 경우에만 연다.

- 당겨서 새로고침
- 그룹·프로필 게시물 생성과 수정
- 그룹 가입·탈퇴·초대 수락

나머지는 세션을 건드리지 않는다.

- 게시물 삭제는 캐시에서 그 글만 덜어낸다.
- 고정, 신고 처리, 카테고리 변경은 해당 그룹의 게시물 목록과 상세만 무효화한다.
- 댓글 수와 반응은 `["posts", "engagement", postId]` 표시용 overlay에만 기록한다. 이 overlay를
  비우는 것은 당겨서 새로고침뿐이다. 규칙은 `app/features/posts/AGENTS.md`에 있다.
- 댓글 뒤에는 route를 재검증하지 않는다. 펼쳐 둔 답글과 불러온 이전 페이지가 초기화된다.

### 그룹

- 가입·가입 요청·요청 취소·탈퇴: 그룹 홈, 탐색, 해당 상세, 멤버 키
- 고정: 그룹 홈, 해당 상세
- 설정·이미지·역할·소유권 변경: 해당 상세, 그룹 홈, 탐색, 멤버 키
- 게시물·카테고리 변경: 해당 그룹의 게시물·카테고리·상세
- 삭제 또는 접근 상실: 해당 그룹의 캐시를 즉시 제거하고 그룹 홈과 탐색을 무효화한다.
- 다른 사람이 권한을 회수한 경우는 열린 그룹 화면이 focus 복귀 때 `["groups"]`를 stale 처리하고
  다시 읽는다.

### 알림

- 셸 뱃지는 `["notifications", "badge"]` 쿼리가 소유한다. Realtime 변경과 focus 복귀는 이 키만
  무효화하고, 사용자가 `/noti`에 있을 때만 알림함 route를 함께 재검증한다. 뱃지를 게이트 로더에
  두지 않는 이유는, 그러면 뱃지 하나 때문에 지금 화면의 로더까지 다시 돌기 때문이다.
- 알림함 이전 페이지는 그 화면에만 병합하고 벗어나면 버린다.
- 알림을 열면(알림함 행, `/noti/open`) 목적지로 가기 전에 뱃지와 모든 그룹의 게시물 목록
  (`["groups", "posts"]`)을 무효화한다. 목록은 다시 읽지 않고 stale 표시만 한다. 알림은 그룹
  목록이 바뀌었다는 신호인데, 두지 않으면 상세 밑에 깔리는 그룹 로더가 2분 캐시의 옛 목록을 쓰고
  상세를 닫아도 그 목록이 남는다.
- Web Push 구독 정보는 캐시하지 않는다. 권한 안내를 처리했는지만 `localStorage`에 둔다(§7).

## 5. 라우터와의 역할 분리

- React Router는 URL, redirect, route error, action 이후 재검증을 맡는다.
- TanStack Query는 중복 제거, 신선도, 메모리 보관, 무효화를 맡는다.
- 로더가 넘긴 값만 그리는 화면은 무효화해도 다시 그려지지 않는다. 지금 화면도 바뀌어야 하면 route
  재검증을 함께 쓰거나 화면이 캐시를 구독한다.
- `shouldRevalidate`는 서버 데이터와 무관한 URL 상태(`post`, `tab` 등)만 거른다.

## 6. 보안 및 점검 목록

- 쿼리 키에 비밀번호, 초대 토큰, signed URL을 넣지 않는다.
- Storage URL은 공용 서명 캐시(`app/shared/supabase/signed-urls.ts`)로만 만든다. 직접 서명하면 매번
  토큰이 바뀌어 이미지를 다시 받고, 모듈 수준 Map은 로그아웃 때 비워지지 않는다.
- 계정을 바꾼 뒤 확인한다: 이전 사용자의 데이터가 첫 화면에 보이지 않는지, Cache Storage의
  `kmla-online-storage-media`가 비었는지. 로그아웃 없이 탭만 닫고 다른 사람이 로그인하는 경로도 본다.
- 그룹 탈퇴·삭제·권한 회수 뒤 접근할 수 없는 캐시가 즉시 사라지는지 테스트한다.
- 새 mutation이나 새 캐시 영역을 추가하면 이 문서를 먼저 갱신한다.

## 7. 브라우저 저장소

`localStorage`에는 계정과 무관한 기기 취향과, 그 계정의 데이터가 들어간다. 새 키를 추가할 때 어느
쪽인지 정하고 아래 표에 적는다.

계정 데이터는 `app/shared/lib/user-scoped-storage.ts`가 소유하고, 저장된 주인이 현재 사용자와 다르면
`syncUserScopedStorage()`가 Cache Storage와 함께 비운다. 지우기가 끝나기 전에는 새 사용자 화면을
그리지 않는다. 기능 코드가 직접 지우지 않는다.

| 키                                               | 구분 | 비고                                         |
| ------------------------------------------------ | ---- | -------------------------------------------- |
| `kmla-online:timetable:v1`                       | 계정 | 진짜 저장소는 DB이고 이 값은 첫 페인트용이다 |
| `kmla-online:visited-posts:v1`                   | 계정 | 열어 본 게시물 id                            |
| `kmla-online:search-recent:v1`                   | 계정 | 검색한 사람·그룹 이름                        |
| `kmla-online:storage-owner:v1`                   | 계정 | 위 값들의 현재 주인                          |
| `kmla-online-storage-media` (Cache Storage)      | 계정 | Storage 이미지 본문                          |
| `kmla-online:posts-view:v1`                      | 기기 | 카드/목록 보기                               |
| `kmla-online:experimental-features:v1`           | 기기 | 실험 기능 토글                               |
| `kmla-online:pwa-install-preference`             | 기기 | 지우면 로그아웃마다 설치 안내가 다시 뜬다    |
| `kmla-online:notification-prompt:v2:<profileId>` | 계정 | 키에 profileId가 있어 이미 격리되어 있다     |

Supabase 세션은 `signOut()`이 지우고, 회원가입 초안(`sessionStorage`)도 함께 비운다.
