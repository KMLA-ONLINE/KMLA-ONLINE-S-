# 홈 통합 피드 알고리즘

## 0. 이 문서의 위치

이 문서는 홈 통합 피드의 후보 선별부터 응답까지를 담은 **단일 기술 참조본**이다. 랭킹 수식, `#업`, 출처 제한, 피드 세션의 구현 규칙은 여기서 끝난다.

- 제품 요구사항의 원본은 [홈 통합 피드 기능 명세](functional-spec/feed.md)이고, 작성 신원과 접근 권한 규칙은 [게시물 및 상호작용 기능 명세](functional-spec/posts.md)를 따른다. 요구사항이 바뀌면 그 문서를 먼저 고치고 이 문서를 맞춘다.
- 실제 구현은 [supabase/schemas/41-feed.sql](../supabase/schemas/41-feed.sql), 검증은 [supabase/tests/integrated_feed.test.sql](../supabase/tests/integrated_feed.test.sql)이다.
- 이전에 나뉘어 있던 랭킹 기술 설계와 v1 제안 문서를 이 문서로 합쳤다. 검토 단계에서 채택하지 않은 제안의 상세는 git 이력에 남아 있다.

피드는 추천 시스템이 아니라, 최신순을 중심으로 최근 상호작용과 출처 다양성을 약하게 반영하는 규칙 기반 목록이다. 한 페이지는 20개다.

### 1.2 알고리즘

```text
── 첫 페이지 (page_token 없음) ─────────────────────────────────
create_feed_session(me):
  프로필 단위 advisory lock                    -- 동시 생성 직렬화
  내 세션 중 expires_at <= now 인 것 삭제
  if 내 세션 중 created_at >= now - 5초 인 것 있음:
      return 그 세션                           -- 중복 첫 페이지 요청
  최신 7개만 남기고 삭제                        -- 새 세션 포함 최대 8개
  feed_epoch := statement_timestamp()
  세션 생성, expires_at := feed_epoch + 24시간

  후보 := { post | published_at <= feed_epoch
                 and deleted_at is null
                 and can_access_feed_post(post, me) }   -- §2

  각 후보의 rank_time 계산 후                             -- 아래 순위 시각
  정렬: rank_time DESC, published_at DESC, post_id DESC

  position := 1
  while 후보 남음:
      if (position - 1) % 20 == 0: 페이지 카운터 초기화
      선택 := 순위 높은 순으로 훑어
                 페이지당 제한(개인 4개 / 그룹 10개) 미만이고
                 연속 제한(개인 2개 / 그룹 3개)에 걸리지 않는 첫 후보
      if 선택 없음: 선택 := 남은 후보 중 순위 1위        -- 제한 완화
      feed_session_posts[position] := 선택
      position := position + 1                          -- 전체 순서 확정

── 순위 시각 ───────────────────────────────────────────────────
feed_rank_time(post):
  age   := feed_epoch - published_at
  fresh := 0 <= age < 6시간

  t := published_at                               -- 6시간이 지났으면 이게 끝
  if fresh:
      t := t + min(4분 × R + 8분 × C,
                   max(0, 40분 × (1 - age / 6시간)))
             - (생탐이면 60분 else 0)
             - (프로필 사진·커버 활동이면 10분 else 0)
  if 유효 #업 있음:
      t := max(t, 마지막 유효 #업 시각)            -- 더하지 않고 바닥값으로만
  return t

  R = feed_epoch 시점의 반응 수                     -- §3.4
  C = 남이 쓴 삭제되지 않은 최상위 댓글 수 (#업 제외)  -- §3.5
  6시간이 지난 게시물은 R = C = 0으로 둔다

── 이후 페이지 (page_token 있음) ───────────────────────────────
list_feed_posts(token):
  인증된 승인 프로필 아니면              -> 42501
  내 세션의 미만료 토큰 아니면            -> 22023
  return 확정 순서에서 position > after_position 이면서
         can_access_feed_post(post, me)가 지금도 참인 앞의 20개
         + 뒤에 더 있으면 다음 토큰
```

핵심 원칙은 두 가지다.

- **순위는 세션 생성 시점에 한 번만 확정한다.** 같은 세션 안에서는 새 게시물·반응·댓글·`#업`이 중복, 누락, 순서 변경을 만들지 않는다.
- **접근 권한은 매 페이지 다시 검사한다.** 세션은 과거 스냅샷일 뿐 권한을 부여하는 자료가 아니다.

## 2. 후보 선별

`private.can_access_feed_post(post_id, profile_id)`가 단일 판정 지점이다. 세션 생성과 페이지 반환 양쪽에서 같은 함수를 호출한다.

공통 조건은 `published_at is not null`, `published_at <= feed_epoch`, `deleted_at is null`이다.

### 2.1 그룹 게시물

- 보는 사용자가 **현재** 그 그룹의 멤버이고 그룹이 삭제되지 않았을 때 포함한다.
- 탈퇴하면 즉시 제외되고, 재가입하면 탈퇴 기간에 올라온 게시물도 다시 후보가 된다.
- 그룹 내부 고정(`pinned_at`)은 홈 피드 순위에 반영하지 않는다.

### 2.2 개인 게시물

`visibility = 'public'`이고 타임라인 당사자가 승인·미삭제 프로필이어야 한다. 그 위에 두 분기가 있다.

| 분기             | 조건                | 노출 대상                                                             |
| ---------------- | ------------------- | --------------------------------------------------------------------- |
| 본인 타임라인 글 | `author = timeline` | 모든 사용자                                                           |
| 생탐             | `author ≠ timeline` | 보는 사용자와 **타임라인 당사자**의 관련 기수가 겹치고 성별이 같을 때 |

생탐 판정은 작성자가 아니라 대상자를 기준으로 한다. 작성자의 기수와 성별은 보지 않는다.

성별은 기수와 독립된 축이다. 복학생의 `cohort + 1` 확장은 그대로 두되, 확장으로 겹친 기수라도 성별이 다르면 제외한다. 교사는 `gender`가 `NULL`이라 비교가 성립하지 않는데, 애초에 관련 기수도 비어 있어 결과는 같다.

### 2.3 관련 기수

`private.feed_profile_cohorts(profile_id)`가 반환하는 배열이다. 승인·미삭제 프로필만 값을 갖는다.

| 대상                            | 관련 기수                                               |
| ------------------------------- | ------------------------------------------------------- |
| 재학생                          | `[cohort]`                                              |
| 복학생 (`is_returning_student`) | `[cohort, cohort + 1]`                                  |
| 졸업생                          | 같은 기수의 승인된 재학생이 실제로 있을 때만 `[cohort]` |
| 교사 및 그 외                   | `[]`                                                    |

빈 배열이면 어떤 기수와도 겹치지 않으므로 생탐 후보를 받지 못한다. 본인 타임라인 글은 이 조건과 무관하게 계속 보인다.

### 2.4 프로필 사진·커버 활동

`activity_kind`가 있는 개인 게시물에는 위 조건에 더해 **한 단계 좁은 조건**을 적용한다. 다음 중 하나를 만족해야 한다.

- 활동 당사자가 보는 사용자 본인이다.
- 활동 당사자가 교사다.
- 보는 사용자와 활동 당사자의 저장된 `cohort`와 `gender`가 **모두** 같다.

생탐과 달리 이 판정에는 복학생 확장(`cohort + 1`)을 사용하지 않는다. 기수가 정확히 같아야 한다. 성별 조건은 두 판정이 동일하다.

### 2.5 세션과 접근 권한의 관계

피드 세션은 순서를 기억하는 자료일 뿐 접근 권한을 부여하는 자료가 아니다.

- 각 페이지를 반환하기 직전에 현재 승인 상태, 그룹 멤버십, 공개 범위, 게시·삭제 상태와 RLS를 다시 검사한다.
- 세션 생성 뒤 접근을 잃은 게시물은 즉시 제외하고, 빈자리는 같은 세션의 다음 후보로 채운다.
- 반대로 세션 생성 뒤 새로 얻은 멤버십이나 공개 전환으로 접근 가능해진 게시물은 **새 세션부터** 반영한다. 진행 중인 세션에 끼워 넣지 않는다.

즉 과거 스냅샷은 현재 접근 제한을 우회할 수 없고, 현재 권한이 넓어졌다고 해서 진행 중인 목록의 순서를 흔들지도 않는다.

## 3. 랭킹

### 3.1 기준 시각

첫 페이지 요청을 처리하는 트랜잭션의 `statement_timestamp()`를 `feed_epoch`으로 확정한다. 작성 시각은 `published_at`이며 초안 생성 시각이 아니다.

### 3.2 rank_time

`private.feed_rank_time()`이 게시물 하나의 정렬 시각을 계산한다.

```text
age   = feed_epoch - published_at
fresh = (published_at <= feed_epoch) and (age < 6시간)

natural   = fresh 이면 published_at + boost - 생탐 보정 - 활동 보정
            아니면   published_at

rank_time = 유효 #업이 있으면 max(natural, 마지막 유효 #업 시각)
            아니면            natural

boost     = min(4분 × R + 8분 × C, max(0, 40분 × (1 - age / 6시간)))
생탐 보정 = 60분 (author ≠ timeline인 개인 게시물)
활동 보정 = 10분 (fresh인 프로필 사진·커버 활동)
```

- `#업`은 상호작용 보정을 다시 얹지 않는다. 둘 중 높은 쪽을 고를 뿐이다. 따라서 `#업`이 순위를 낮추는 일은 없고, 이미 보정으로 더 위에 있는 글은 그 자리를 지킨다.
- 6시간이 지나면 `boost`, 생탐 60분, 활동 10분이 모두 사라지고 사실상 최신순으로 돌아간다.
- 정렬 키는 `rank_time DESC, published_at DESC, post_id DESC`다. 동점은 변하지 않는 키로만 해소한다.

### 3.3 감쇠와 상한

`boost`의 상한은 40분에서 6시간에 걸쳐 0까지 선형으로 줄어든다.

| 작성 후 경과 | 보정 상한 |
| ------------ | --------: |
| 방금         |      40분 |
| 1시간        | 33분 20초 |
| 2시간        | 26분 40초 |
| 3시간        |      20분 |
| 4시간        | 13분 20초 |
| 5시간        |  6분 40초 |
| 6시간 이상   |       0분 |

원시 보정값이 상한에 닿는 지점은 반응 10개(4분 × 10) 또는 랭킹 댓글 5개(8분 × 5)다. 그 이상은 더 올라가지 않는다.

예를 들어 반응 5개와 랭킹 댓글 2개가 달린 글의 원시 보정은 `4 × 5 + 8 × 2 = 36분`이다. 방금 올린 글이라면 36분이 그대로 붙어 36분 뒤에 올린 무반응 게시물과 같은 자리에 서고, 3시간 지난 글이라면 상한 20분으로 잘린다. 같은 글이 생탐이라면 여기서 다시 60분을 빼므로, 36분을 받아도 실제로는 24분 아래에 배치된다.

### 3.4 R — 반응 수

`private.post_reaction_count_events`에서 `occurred_at <= feed_epoch`인 `delta`의 합이다.

반응 추가는 `+1`을, 반응 제거는 `-1`을 각각 발생 시각과 함께 남기는 append-only 이벤트 로그다. 현재 집계표가 아니라 이 로그를 쓰기 때문에 `feed_epoch` 시점의 값을 정확히 복원할 수 있고, 세션 생성 이후의 반응 변화가 순위에 섞이지 않는다.

### 3.5 C — 랭킹 댓글 수

다음을 모두 만족하는 댓글만 센다.

- `depth = 0` (최상위 댓글)
- `deleted_at is null`
- `created_at <= feed_epoch`
- `btrim(body) <> '#업'`
- 댓글의 **실제 작성자**가 게시물의 **실제 작성자**와 다르다

작성자 비교는 표시용 신원이 아니라 `private.comment_authors`와 `private.post_authors`의 실제 작성자를 사용한다. 따라서 익명이나 운영진 명의로 자기 글에 단 댓글도 제외된다.

`R`과 `C`는 6시간 이내인 게시물에서만 계산하며, 그 외에는 0으로 취급한다. `#업`이 있는 게시물도 아직 6시간 이내라면 계산한다. `#업` 시각과 비교할 원래 순위가 필요하기 때문이다.

## 4. `#업`

오래된 그룹 공지 등을 홈 통합 피드 위쪽으로 다시 올리는 피드 전용 신호다.

### 4.1 유효 사건 조건

`private.capture_effective_feed_bump()`가 댓글 INSERT 트리거로 판정한다. 다음을 모두 만족할 때만 `private.feed_bump_events`에 사건을 남긴다.

- 대상이 게시·미삭제된 **그룹 게시물**이다. 개인 게시물은 `#업` 대상이 아니다.
- 작성자가 그 게시물에 현재 댓글을 쓸 수 있다. 댓글 자체가 거부되면 사건도 없다.
- 댓글 `depth = 0`이다. 답글은 제외한다.
- 작성 신원이 `identified` 또는 `staff`다. 익명 `#업`은 무효다.
- 앞뒤 공백을 제거한 전체 본문이 정확히 `#업`이다.
- 같은 게시물의 직전 유효 사건으로부터 **1시간** 이상 지났다.

쿨다운 검사와 사건 삽입은 `pg_advisory_xact_lock`으로 게시물 단위 직렬화한다. 동시 요청이 쿨다운을 우회할 수 없다.

### 4.2 사건의 성질

- 사건은 `post_id`, `comment_id`, `effective_at`을 가진 **변경 불가능한 기록**이다. UPDATE·DELETE는 트리거가 `55000`으로 거부한다.
- 댓글 **수정**으로는 사건을 만들 수 없다. INSERT만 트리거된다.
- 유효 사건의 원인 댓글은 작성자와 운영진을 포함해 수정·삭제할 수 없다. 과거 세션의 순위 근거와 감사 가능한 쿨다운 기준을 보존하기 위해서다.
- 쿨다운 중에 단 `#업`은 일반 댓글로 남고 사건을 만들지 않는다.

### 4.3 효과와 표시

- 마지막 유효 사건 시각을 `rank_time`의 **바닥값**으로 쓰며, 다음 유효 사건이 생길 때까지 유지된다. 원래 순위가 더 높으면 그 순위를 그대로 둔다. `#업`은 게시물을 올리거나 유지할 뿐 결코 내리지 않는다.
- 그래서 이미 상호작용 보정으로 위에 있는 신선한 글에 `#업`을 달면 순위는 그대로이고 1시간 쿨다운만 소모된다. 오래된 글에 쓰라고 만든 기능이다.
- `published_at`은 바꾸지 않는다. `#업`만으로 새 글이 되지 않는다.
- 그룹 내부 정렬에는 영향을 주지 않는다.
- 화면 댓글 수에는 포함하되 `C`에서는 제외한다.
- 댓글 읽기 RPC는 사건의 원인 댓글인지 여부를 `is_effective_feed_bump`로만 알려 준다. 클라이언트는 그 값이 참일 때만 파란색으로 표시하고, 이벤트 관계 자체는 노출하지 않는다.

## 5. 출처 제한

출처는 그룹 게시물이면 **그룹**, 개인 게시물이면 **실제 작성자**다. 생탐도 개인 게시물이므로 작성자를 출처로 쓴다. 서로 다른 그룹은 서로 다른 출처다.

| 출처                      | 연속 제한 | 페이지 제한 |
| ------------------------- | --------: | ----------: |
| 같은 사용자의 개인 게시물 |       2개 |         4개 |
| 같은 그룹의 게시물        |       3개 |        10개 |

`create_feed_session()`은 순위표를 앞에서부터 훑으며 두 제한을 모두 만족하는 첫 후보를 뽑아 `position`을 부여하고, 후보가 떨어질 때까지 반복해 **전체 순서를 한 번에 확정**한다.

- 제한에 걸린 후보는 버리지 않고 뒤로 밀린다. 별도의 지연 큐를 두지 않아도 확정된 `position`이 같은 역할을 한다.
- 제한을 만족하는 후보가 하나도 없으면 남은 후보 중 순위가 가장 높은 것을 그대로 배치한다. 즉 후보가 부족할 때는 제한보다 **채우기를 우선**한다.
- 완화가 일어나 순위가 낮은 후보가 먼저 나가더라도 밀린 후보를 버리지 않는다. 그대로 뒤 자리에 남는다.
- 완화는 출처 제한에만 적용된다. 접근 불가능한 게시물은 어떤 경우에도 완화 대상이 아니다.
- 페이지 제한 카운터는 `position` 20개마다 초기화하고, 연속 제한은 그 경계를 넘어 이어 계산한다.

이 절차의 목적은 두 제한을 실제로 적용하면서도 후보가 있는 한 페이지 크기를 채우고, 특정 출처의 게시물이 페이지네이션 과정에서 영구히 누락되지 않게 하는 것이다.

## 6. 세션과 페이지네이션

### 6.0 왜 커서가 아니라 세션인가

`feed_epoch`만 담은 커서를 들고 다니며 페이지마다 순위를 다시 계산하는 방식은 쓸 수 없다. 반응 추가와 취소, 댓글 삭제, 새 `#업`이 계속 일어나므로 변경 가능한 집계에서 과거 시점의 순위를 정확히 복원할 방법이 없기 때문이다. 복원에 실패하면 페이지를 넘길 때 게시물이 중복되거나 누락된다.

그래서 첫 페이지 요청이 서버 측 세션을 만들고, 같은 트랜잭션 스냅샷에서 다음을 한 번에 확정한다.

- `feed_epoch`
- 후보 게시물과 그 시점의 정렬 키
- 동점 해소 순서
- 출처 제한을 적용한 뒤의 최종 순서, 즉 밀린 후보를 포함한 전체 `position`

확정한 순위와 상호작용 수는 다시 계산하지 않는다. 따라서 같은 세션 안에서는 새 게시물, 반응, 댓글, 댓글 삭제, `#업` 어느 것도 중복·누락·순서 변경을 만들지 않는다.

### 6.1 세션 생성 — `private.create_feed_session()`

1. 프로필 단위 advisory lock으로 동시 생성을 직렬화한다.
2. 만료된 세션(`expires_at <= epoch`)을 정리한다.
3. **5초 이내**에 만든 유효 세션이 있으면 새로 만들지 않고 재사용한다. 중복 첫 페이지 요청 방지다.
4. 최신 7개를 남기고 나머지를 삭제한다. 새 세션을 포함해 사용자당 활성 세션은 최대 **8개**다.
5. `feed_epoch`과 `expires_at = feed_epoch + 24시간`으로 세션을 만들고, 확정한 순서를 `feed_session_posts`에 저장한다.

### 6.2 페이지 반환 — `public.list_feed_posts(p_page_token)`

- 인증된 승인 프로필이 아니면 `42501`로 거절한다.
- 토큰이 없으면 첫 페이지이며, 세션을 만들거나 재사용한다.
- 토큰은 클라이언트가 해석하거나 조작하지 않는 불투명 UUID다. 본인 세션의 미만료 토큰이 아니면 `22023`으로 거절한다. 만료·제거된 세션을 같은 `feed_epoch`인 것처럼 조용히 재생성하지 않는다.
- `position > after_position`이면서 **지금 접근 가능한** 항목만 순서대로 20개 반환한다. 세션 생성 후 접근을 잃은 게시물은 건너뛰고 빈자리를 다음 후보로 채운다.
- 뒤에 접근 가능한 항목이 남아 있을 때만 다음 토큰을 발급한다.

접근 불가 항목을 건너뛰므로 실제 반환 페이지의 경계는 확정 시점의 20개 블록과 어긋날 수 있다. 출처 제한의 "페이지당" 개수는 확정 시점 블록을 기준으로 한다.

새 게시물, 새 상호작용, 새 `#업`은 5초 구간이 지난 뒤 새로고침해 만든 **새 세션**부터 반영된다.

### 6.3 세션 자료의 보호

세션과 랭킹 이벤트는 모두 `private` 스키마에 있고 클라이언트 grant가 없다. 세션은 사용자별 자료이므로 다른 사용자가 읽거나 이어받을 수 없으며, 만료된 세션은 `private.cleanup_expired_feed_sessions()`로 정리한다.

## 7. 응답

한 페이지는 게시물 20개와 다음 페이지 토큰을 함께 반환하며, 카드 보기와 목록 보기가 게시물별 추가 조회 없이 렌더링할 수 있는 정보를 모두 담는다. 카드와 목록은 같은 세션과 같은 순서를 쓴다.

작성 신원 표시는 [게시물 및 상호작용 기능 명세](functional-spec/posts.md)를 따른다. 피드도 예외가 아니다. 실제 작성자를 감추는 것은 익명 게시물뿐이고, 운영진 명의는 실제 작성자의 이름과 프로필 사진을 운영진 배지와 함께 내려보낸다.

댓글 수와 반응 수는 화면 표시용 현재 값이며, 세션에 확정된 랭킹 입력과는 다른 값이다. 두 값을 혼동하지 않는다.

### 7.1 화면 경계

- 오늘의 생일 영역은 연기한다. 생일 여부는 후보 선별에도 순위에도 쓰지 않는다.
- 홈 피드 응답에는 읽음 상태, 새 글 표시, 방문 표시에 해당하는 자료가 없다. 클라이언트도 그런 상태를 두지 않는다.

## 9. 하지 않는 것

- 읽음 상태 서버 저장, 새 게시물 점·개수, 게시물별 로컬 방문 표시
- 오늘의 생일 영역 및 생일의 후보·랭킹 반영 (명시적 연기)
- 팔로우·친구 기반 피드, 개인별 추천 점수, 관심사 추천
- 클릭·조회 기록 기반 랭킹, AI/ML·임베딩·협업 필터링, 트렌딩 피드
- 개인 게시물의 `#업`, 그룹 내부 정렬에 대한 `#업` 반영
- 6시간이 지난 인기글을 반응만으로 다시 상단에 올리는 처리
- 개인·그룹 게시물의 강제 비율, 작성자·그룹별 하루 게시물 제한
- 운영진 명의를 익명처럼 다루어 실제 작성자를 감추는 처리

## 10. 검증 기준

- 같은 세션의 여러 페이지에서 새 상호작용과 `#업`이 발생해도 중복·누락·기존 순서 변경이 없다.
- 댓글 수정은 `#업` 사건을 만들지 않고, 유효 사건의 원인 댓글을 수정·삭제해도 사건은 남는다.
- 같은 게시물에 동시에 등록한 `#업` 중 1시간 쿨다운을 통과한 사건은 최대 하나다.
- 상호작용 보정이 붙은 6시간 이내 게시물에 `#업`을 달아도 순위가 내려가지 않는다.
- 연속 제한은 페이지 경계를 넘어 적용되고, 페이지 제한은 새 페이지에서 초기화된다.
- 제한으로 미룬 게시물은 후속 페이지 또는 부족분을 채우는 완화 단계에서 반환된다.
- 세션 중 그룹 탈퇴, 승인 취소, 비공개 전환 또는 삭제가 발생하면 다음 응답에서 해당 게시물을 반환하지 않는다.
- 프로필 미디어 활동은 본인·교사·동일 기수 및 성별에게만 보이고, 졸업생 생탐 조건은 현재 승인된 재학생 기수와 대조한다.
- 관련 기수가 겹쳐도 대상자와 성별이 다르면 생탐을 받지 않는다.
- 반응을 추가했다가 제거해도 `feed_epoch` 시점의 `R`이 정확히 복원된다.
- 홈 피드 응답과 클라이언트 상태에 읽음·새 글·방문 표시 자료가 없다.
