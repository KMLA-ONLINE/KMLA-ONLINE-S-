# 아키텍처 결정 기록 (ADR)

여러 문서나 feature에 걸친 결정의 이유, 버린 대안, 결정 시점을 남긴다. ADR은 현재 규칙의
정본이 아니다. 지금 무엇이 규칙인지는 명세·기술 설계·`structure.md`·feature `AGENTS.md`가
소유하고, ADR은 그 규칙을 왜 그때 그렇게 정했는지를 기록한다.

## 기록 위치

| 위치                          | 담는 내용                                      | 판별 질문                                          | 수명                                 |
| ----------------------------- | ---------------------------------------------- | -------------------------------------------------- | ------------------------------------ |
| 코드 주석                     | 한 모듈·함수 안에서만 의미 있는 이유           | 이 코드가 사라지면 이유도 함께 사라지는가?         | 코드와 함께 바뀌고 삭제된다          |
| feature `AGENTS.md`           | 한 feature 안에서 지켜야 할 불변식             | 이 feature를 고치는 사람이 꼭 알아야 하는가?       | 현재 시점 기준으로 고친다            |
| 명세·기술 설계·`structure.md` | 현재 유효한 제품 요구·구현 정책과 그 결론      | 지금 무엇이 규칙인가?                              | 현재 시점 기준으로 고친다            |
| ADR                           | 여러 문서·feature에 걸친 결정의 이유·대안·시점 | 왜 다른 안을 버렸고 언제 바뀌었는지 추적해야 하나? | 본문을 고치지 않고 새 ADR로 대체한다 |

위에서부터 차례로 판별한다. 국소적인 이유는 아래 기준을 충족해도 코드 주석에 쓴다. 결정이
현재 규칙을 바꾸면 소유 문서를 먼저 고치고, 아래 기준을 충족할 때만 ADR을 더한다. ADR은
소유 문서를 대체하지 않는다.

## 기록 기준

다음 세 가지가 모두 참일 때만 ADR을 쓴다.

1. **되돌리기 어렵다**: 나중에 마음을 바꾸는 비용이 크다.
2. **맥락 없이는 의아하다**: 다음 사람이 코드나 문서를 보고 "왜 이렇게 했지?"라고 묻게 된다.
3. **실제 trade-off의 결과다**: 진짜 대안이 있었고 구체적인 이유로 하나를 골랐다.

하나라도 빠지면 쓰지 않는다. 쉽게 되돌릴 수 있으면 되돌리면 되고, 의아하지 않으면 아무도 묻지
않으며, 대안이 없었다면 기록할 이유도 없다.

## 중복 방지

- 소유 문서에는 결론과 함께 해당 ADR로 가는 `근거: ADR-NNNN` 링크 한 줄을 둔다. ADR에 현재
  규칙 전체를 복사하지 않는다.
- 코드 주석은 그 ADR이 유일한 근거일 때만 `ADR-NNNN`을 인용한다. 이유를 주석에 다시 풀어 쓰지
  않는다.
- 같은 결정을 주석, 소유 문서, ADR 세 곳에 모두 설명하지 않는다.
- 국소적인 결정의 주석에는 버린 대안이나 이전 구현을 자명하지 않을 때만 한 문장으로 적는다.
  여러 곳에 걸친 결정의 경위는 ADR에 둔다.

## 작성 규칙

- 사용자가 기록을 승인하고 쓰기가 허용된 모드일 때만 만든다. Plan 모드에서는 대화로 제안한다.
- 파일명은 `NNNN-영문-kebab-case.md`다. 번호는 이 디렉터리의 가장 큰 번호에 1을 더한다.
  번호는 안정적인 식별자이므로 재사용하거나 다시 매기지 않는다.
- 한국어로 쓴다. 코드·경로·식별자는 원문을 유지한다.
- 새 ADR은 아래 목록에 추가한다. 이 디렉터리는 [문서 안내](../README.md)에 등록되어 있으므로
  개별 ADR을 그곳에 다시 등록하지 않는다.
- 채택한 ADR의 본문은 고치지 않는다. 오탈자와 깨진 링크 수정, 상태 줄 갱신만 허용한다. 결정이
  바뀌면 새 ADR을 쓰고 이전 ADR의 상태를 `ADR-NNNN으로 대체`로 바꾼다.

### 템플릿

```md
# 결정의 짧은 제목

**상태**: 채택 · **날짜**: YYYY-MM-DD

맥락, 결정, 이유를 1~3문장으로 쓴다.
```

ADR은 한 문단이어도 된다. 가치는 결정이 있었다는 사실과 그 이유에 있다. 다음 절은 실제로
필요할 때만 더한다.

- **검토한 대안**: 버린 이유가 자명하지 않아 다시 제안될 수 있을 때
- **영향**: 자명하지 않은 후속 영향을 알려야 할 때

상태는 `제안`, `채택`, `폐기`, `ADR-NNNN으로 대체` 중 하나다.
