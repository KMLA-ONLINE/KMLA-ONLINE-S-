# 릴리즈 공지를 PR에서 모으지 않고 릴리즈 후 생성

**상태**: 채택 · **날짜**: 2026-11-13

[ADR-0002](0002-release-dashboard-and-calver.md)는 사용자 공지를 각 PR 본문의 `## 릴리즈` 절
`- 공지:` 줄에서 모았다. 무엇을 알릴지 작성자마다 판단이 달라 버그 수정이나 UI 변경이 자주 빠졌고,
운영자는 매 릴리즈 변경 목록으로 공지를 따로 만들고 있었다. 그래서 공지는 PR에서 모으지 않고, prod
배포가 성공한 뒤 그 릴리즈 PR들의 `## 왜`·`## 바뀌는 동작`을 저장소의 프롬프트와 함께 Gemini에
넘겨 초안을 만든다. 초안은 체크리스트 이슈에 들어가고 사람이 다듬어 게시한다. `## 릴리즈` 절은 할
일만 담는다. 현재 절차는 [환경 가이드 §5.5](../DOCKER.md#55-릴리즈-대기-목록과-릴리즈-pr)에 있다.

## 검토한 대안

- **템플릿에 공지 작성을 강제**: 빈 칸을 채우게 해도 무엇이 "알릴 변화"인지는 여전히 작성자 판단이라
  누락이 줄지 않는다. 릴리즈 단위로 묶어 표현을 맞추는 일도 남는다.
- **dev 배포마다 초안을 갱신해 릴리즈 PR에 표시**: merge 전에 볼 수 있지만 배포마다 모델을 부르고
  문구가 매번 달라진다. 실제로 나간 변경과 정확히 맞는 것은 배포 후의 범위다.
- **초안을 바로 외부 채널에 게시**: 모델 출력은 틀릴 수 있어 사람이 확인한 뒤 게시한다.
